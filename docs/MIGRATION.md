# 이관 기록 — 보존할 증거와 교체할 구현

새 개발의 기준은 이 저장소 루트의 [설계 계약](../DESIGN.md)이다. 임시 실험 디렉터리나 로컬 워크플로 파일은 배포·빌드·실행의 전제가 아니다. 이 문서는 **구현을 어떤 기준으로 교체하는지** 기록한다. 옛 결과가 새 엔진의 합격을 의미하지는 않는다.

## 시나리오의 출처

이관 전 연구 제안 「PQTLS 벤치마크 프레임워크 제안_ver1」의 S0–S4와 서버 인증/mTLS 의미는 그대로 유지한다. 새 체크아웃에서는 연구 작업 폴더 없이도 [설계 §4](../DESIGN.md#scenarios)가 시나리오 전체와 양측 측정 끝점을 제공해야 한다. 옛 [프레임워크 설계](TURTLE%20벤치마크%20프레임워크%20구현%20설계.md)와 [검증 기록](validation.md)은 당시 동작·용어를 확인하기 위한 자료이며 새 공개 함수표가 아니다.

## 배포 언어 경계

- **허용:** TURTLE이 제공하는 코어, 역할 프로그램, 연동 코드, 수집기·분석기, 예제, 테스트, 빌드·검사 도구에는 C, C++, POSIX 셸, Make/CMake만 사용한다. 셸 진입점에서 다른 언어의 인터프리터를 불러 같은 제한을 우회하지 않는다.
- **데이터와 문서:** Markdown 설명, JSON 명세·fixture·실측 결과, 공개 시험 인증서·패킷 자료는 프로그램 언어가 아니다. 외부 TLS 라이브러리나 OS 도구는 식별 가능한 독립 의존성으로 다루며 그 소스 트리나 개인키를 TURTLE 구현에 복사하지 않는다.
- **배포 경계:** 골든 데이터는 검산 자료이며 런타임 의존성이 아니다. 작업 트리의 확장자뿐 아니라 실제 제품의 설치 파일·실행 진입점과 함께 배포할 아카이브의 내부 멤버도 확인한다.

## 증거 아카이브 이관 영수증

`docs/evidence/scenario-flights.tar.gz`에서 제외한 것은 옛 분석 프로그램 `scenario-flights/rebuild.py`와 표 작성 프로그램 `scenario-flights/format_tables.py`뿐이다. 두 프로그램을 포함한 원본은 Git 객체 `9bee9be:docs/evidence/scenario-flights.tar.gz`에 남는다. 이관본은 원자료를 다시 측정하거나 표를 재생성한 것이 아니다.

| 항목 | 일반 파일 수 | SHA-256 |
|---|---:|---|
| 원래 압축 파일 | 1,226 | `da5354f4c78c9573d310ab6e6deaf062e6854938bac5de251fbcf2ba3f9d4139` |
| 이관한 압축 파일 | 1,224 | `b3060198094bda0f18b2d33c42c5641f64c43556e11fbc4eb69920059a77c523` |
| 보존한 멤버 목록(경로·내용 검산) | 1,224 | `99158d4f7c7791a715394dd94c3034733c0d3c5f95a071770a92d03c2bd58b29` |

검산은 아카이브 순서로 파일마다 **내용 SHA-256(소문자 16진), 공백 두 개, 멤버 경로, LF**를 연결했다. 원본 목록에서 두 경로만 뺀 결과와 이관본의 목록이 바이트 단위로 일치했다. 나머지 두 아카이브와 기존 검증 목록은 변경하지 않았다.
