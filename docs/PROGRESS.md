# 구현 상태와 남은 범위

이 문서는 원래 작업 목록을 전부 완료한 것처럼 표시하지 않습니다. 최신 사용자 요청에 따라 **실제로 실행하고 고칠 수 있는 정상 경로 벤치마크**를 먼저 완성하고, 장비·추가 설계가 필요한 부분을 구별했습니다.

| 작업 | 현재 상태 |
|---|---|
| M0 저장소·규칙 | Git, 모듈별 소스, 별도 테스트 빌드, 확인 스크립트와 명시적 공개 계약을 마련했습니다. |
| M1 새 역할 프로세스 | 표본마다 두 역할을 새로 만들며 실제 TLS와 모의 회귀 시험으로 확인합니다. |
| M2 제어·원자료 | 측정 TCP 밖의 준비 신호, 고정 기록 버퍼, 역할별 JSONL·바이트·키 로그·무효 이유를 남깁니다. |
| M3 컨텍스트 | 입력·저장 계약과 크기 기록은 있습니다. 세 실제 TLS 어댑터는 비어 있지 않은 저장 상태를 아직 지원하지 않습니다. 준비 연결은 별도 지원합니다. |
| M4 인증서 | 로컬 CA와 1~3개 체인, ECDSA·RSA2048·Ed25519 잎 인증서 생성 도구가 있습니다. 세 라이브러리 공통 검증은 ECDSA/P-256입니다. |
| M5 OpenSSL | 서버 인증·상호 인증, 실제 TCP와 선택적인 네이티브 소켓 경로가 있습니다. 네이티브 경로를 시스템 호출 추적 결과로 표시하지 않습니다. |
| M6 비차단 송수신 | 콜백에서 실제 TCP로 보내고 받으며 준비 대기·부분 바이트·호출 경계를 기록합니다. |
| M7 계측 | 단조 시간, 스레드 CPU, 가능한 perf, 별도 힙 모드, 수신 커널 시각, 코어 고정과 환경 정보가 있습니다. 스택·송신/NIC 시각·완전한 관측 비용 보정은 남았습니다. |
| M8 해독 | AES-128-GCM/SHA-256 방향별 스트림과 키 로그를 해독합니다. OpenSSL 메시지 알림과 비교하는 실제 TLS 시험이 있습니다. 다른 암호 방식·변경된 키 스케줄은 미지원으로 남깁니다. |
| M9 세 어댑터 | 고정 판과 공통 프로필, 세 라이브러리의 모든 클라이언트/서버 조합을 실제 TCP로 시험합니다. 라이브러리별 힙 할당 훅을 연결했습니다. |
| M10 검증 실험 | 원자료 재계산·구간 합·바이트 대응·복호화·기능 반복을 자동화했습니다. eBPF/패킷 캡처 시각 대조, 독립 두 번째 어댑터, 자체 벤치마크 대조, 계측 영향의 완전한 실험은 하지 않았습니다. |
| M11 요약·재현 | StQ·분포·독립 부트스트랩·묶음 기록, 순서 무작위화 스크립트와 빌드 의존성 스크립트가 있습니다. 원자료가 있으면 다시 요약할 수 있습니다. |
| M12 연구 기법 재측정 | 인증서와 티켓 설정을 바꾸는 실행 준비까지입니다. BiTHaC·인증서 압축·레코드 크기 제한의 구현과 원 논문 재현은 하지 않았습니다. |
| M13 모의 CA | 설계 쟁점만 별도 메모로 남겼습니다. 세 번째 프로세스나 OCSP 서버를 구현하지 않았습니다. |

## 현재 수치를 해석할 때의 제한

- 기능 시험은 측정값의 정확도나 외부 환경에서의 순위를 증명하지 않습니다. 현재 개발 환경은 WSL이며 클럭·부하를 실험실 조건으로 통제하지 않았습니다.
- 시계 읽기 보정 표본은 연속 계측 읽기의 비용입니다. 사건 추가·스트림 복사·키 로그의 전체 영향까지 포함한 보정값이 아닙니다. 요약은 보정하지 않은 값을 기본으로 합니다.
- 메모리 값은 연결 구간의 라이브러리 요청 힙입니다. 셋업 이후 남아 있는 메모리도 살아 있다면 포함하며 전체 프로세스 메모리나 실제 할당기 내부 순간 최고치와 같지 않습니다.
- 현재 한 역할은 단일 TLS 작업 스레드입니다. 외부 작업 스레드의 연산과 비동기 커널 작업까지 합쳐 센다고 주장하지 않습니다.
- 커널 수신 시각은 별도 원자료입니다. L0 구간 합에 끼워 넣거나 모든 바이트에 대한 정확한 지연으로 변환하지 않습니다.
- 실제 TLS 어댑터의 일부 협상값은 공개 API에서 조회하지 못하거나 고정 허용 목록으로 제한됩니다. 선언과 `incomplete`를 함께 읽어야 합니다.
- 무효 표본은 자동으로 다시 채우지 않습니다. 비정상 종료로 역할 기록이 비어 있으면 `director.txt`에 이유를 남기며 해석기는 완성된 표본인 것처럼 처리하지 않습니다.
- 네이티브 소켓 경로는 진단용입니다. 특히 서버의 첫 수신 경계가 보이지 않아 기본 송수신 구간 보고와 같은 결과를 만들 수 없습니다. 시스템 호출 추적을 붙이기 전에는 기본 경로와의 자동 성능 비교용으로 쓰지 않습니다.

## 다음에 직접 손볼 곳

1. 먼저 `include/turtle/adapter.hpp`와 `docs/adapter-guide.md`를 읽고 대상 연구의 정상 경로를 어댑터 하나로 연결합니다.
2. 같은 프로필·상대 구현·출발 상태·관측 모드에서 원자료를 모읍니다. 다른 실험 조건을 한 분포에 섞지 않습니다.
3. 물리 리눅스 장비에서 perf와 클럭 조건을 확인한 뒤 계측 영향 실험을 설계합니다.
4. 스택·커널 송신·시스템 호출 추적은 각각 관측 의미와 검증 기준을 정한 뒤 추가합니다.
5. 메시지 묶음을 개별 메시지 연산 시간으로 나눌 수 있다는 주장은 새 근거가 생길 때까지 하지 않습니다.
