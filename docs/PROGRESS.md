# 구현 상태와 남은 범위

이 문서는 원래 작업 목록을 전부 완료한 것처럼 표시하지 않습니다. 최신 사용자 요청에 따라 **실제로 실행하고 고칠 수 있는 정상 경로 벤치마크**를 먼저 완성하고, 장비·추가 설계가 필요한 부분을 구별했습니다.

| 작업 | 현재 상태 |
|---|---|
| M0 저장소·규칙 | Git, 모듈별 소스, 별도 테스트 빌드, 확인 스크립트와 명시적 공개 계약을 마련했습니다. |
| M1 새 역할 프로세스 | 표본마다 두 역할을 새로 만듭니다. 준비 연결과 측정 연결 수를 따로 지정하고 소켓을 모두 격리 전에 마련합니다. TLS 이전 소켓 설정을 다시 읽어 실제값을 남기며, 격리 뒤 실제 소켓 생성 실패와 새 PID를 시험합니다. |
| M2 제어·원자료 | 측정 TCP 밖의 준비 신호, 고정 기록 버퍼, 역할별 JSONL·바이트·키 로그·무효 이유를 남깁니다. |
| M3 컨텍스트 | 지휘 프로세스가 역할별 입력을 한 번 읽어 반복마다 같은 저장본을 전달합니다. 모의 구현의 저장·복원과 입력 상태 고정 시험, 크기·지문 기록이 있습니다. 세 실제 TLS 어댑터의 비어 있지 않은 저장 상태와 TLS 세션 재개를 구현했다는 뜻은 아닙니다. 준비 연결은 별도 기능입니다. |
| M4 인증서 | 발급 시각을 한 번 읽고 모든 인증서에 공통 `-300초 .. +3650일` 유효 기간을 적용해 시각 역행 실패를 수정했습니다. ECDSA·RSA2048·Ed25519 잎과 체인 길이 1~3의 9조합을 각 두 번 system OpenSSL 3.0·고정 3.5에서 통과했습니다. 발급 과정의 시각 출력만 실제 검증 시각보다 240초 앞당기는 shim에서도 정상 검증을 유지했습니다. host 시계를 바꾼 시험은 아닙니다. CA 키와 인증서 서명은 ECDSA입니다. |

| M6 비차단 송수신 | OpenSSL callback/native 정상 경로와 관측 가능성을 분리해 구현했습니다. callback은 framework stream·I/O·가능한 kernel receive 사건을 기록하고, native는 이 세 자료를 unavailable로 남깁니다. native client의 호출 경과·CPU는 보존하지만 I/O 분해는 없고, native server의 첫 수신 기반 주 구간은 unavailable입니다. 기존 zero-loss runner의 router AF_PACKET skb metadata 비교와 72×20 전체 반복·원자료 감사를 통과했습니다. wolfSSL·Mbed TLS native는 지원하지 않습니다. |
| M7 계측 | `measurement.channel_observer`로 callback transport 관측자 포인터만 켜고 끌 수 있게 했습니다. 기본값은 true이며 false에서도 같은 callback I/O·버퍼·소켓 timestamp 설정·호출/대기 계측·keylog/plaintext/perf 경로를 유지합니다. 양 역할·양 모드의 공통 호출 경계, 실제 4-batch 교대 실행, 73×20과 원자료 감사를 통과했습니다. 스택·송신/NIC 시각·완전한 관측 비용 보정은 여전히 범위 밖입니다. |
| M8 해독 | 고정 암호군 TLS_AES_128_GCM_SHA256의 방향별 스트림과 키 로그를 해독합니다. OpenSSL 메시지 알림과 비교하는 실제 TLS 시험이 있습니다. 다른 암호군은 미완료 작업이 아니라 범위 밖입니다. 연구 기법이 키 스케줄을 바꾸면 해독 지원 여부를 별도로 밝혀야 합니다. |
| M9 세 어댑터 | 고정 판과 공통 프로필, 세 라이브러리의 모든 클라이언트/서버 조합을 실제 TCP로 시험합니다. 라이브러리별 힙 할당 훅을 연결했습니다. |
| M10 검증 실험 | 원자료 재계산·구간 합·바이트 대응·복호화·기능 반복을 자동화했습니다. eBPF/패킷 캡처 시각 대조, 독립 두 번째 어댑터, 자체 벤치마크 대조, 계측 영향의 완전한 실험은 하지 않았습니다. |
| M11 요약·재현 | StQ·분포·독립 부트스트랩·묶음 기록, 순서 무작위화 스크립트와 빌드 의존성 스크립트가 있습니다. 원자료가 있으면 다시 요약할 수 있습니다. |
| M12 연구 기법 재측정 | 인증서와 티켓 설정을 바꾸는 실행 준비까지입니다. BiTHaC·인증서 압축·레코드 크기 제한의 구현과 원 논문 재현은 하지 않았습니다. |
| M13 모의 CA | 합성 조회, 별도 모의 CA 프로세스, 서비스 원자료와 attempt 원장, 독립 CA 계측을 연결했습니다. 조회 결과는 캐시에 실제 소비하지만 stock TLS 인증서 입력을 대체하지 않습니다. 실제 표준 TLS 고정 검증과 warm request0 gate가 통과했습니다. OCSP/ACME나 실제 인증서 압축·캐싱 기법은 아닙니다. |
| M14 격리 netem | rootless client/server/ca/router 네 data namespace·네 veth 링크, 네 방향 qdisc, offload/MTU readback, skb 관측을 구현했습니다. 고정 N05 64/64 성공, qdisc drop 94, CA 재전송 58, host unchanged와 owned cleanup이 통과했습니다. 정확한 여섯 phase 참조와 fail-closed 원장을 포함한 최종 network-integrity 보고도 완료했습니다. |
| G007 후속 정리 | `lookup.enabled=false`의 정상 TLS를 client/server/router 세 namespace·두 링크·두 TLS 방향으로 실행하고 CA 자원을 만들지 않는 경로, 일반 TLS 보고의 요청·실제 network identity, 엄격한 원장 읽기와 수명주기 파일 책임 분리를 구현했습니다. 실제 순수 TLS 원자료를 보존했고 G007 동결 당시 58개 시험을 각각 20회 통과해 완료했습니다. |
| G008 두 커밋 cutover | M0~M4 기반을 `cd2a5fa`, lookup·Mock CA·netem과 G007을 `3723056`에 나눈 Lore 커밋으로 확정했습니다. 첫 커밋은 45×20, 두 번째 동결 트리는 58×20과 정적 검사를 통과했습니다. cutover 시점의 139개 경로를 모두 분류했고 빌드·결과·OMX 런타임 경로는 무시 규칙으로 제품 이력과 분리했습니다. |
| G009/M5 CLI 상호운용성 | 수정하지 않은 `/usr/bin/openssl` 3.0.13과 세 어댑터의 12조건 원자료 감사를 통과했습니다. 최신 70개 시험을 각각 20회, 총 1,400회 통과했고 이 안의 CLI 조건은 240회입니다. 첫 Mbed TLS 근거 분류 오류는 별도 실패 이력으로 보존하고 명시적 category 회귀 시험으로 수정했습니다. |
| G010/M6 I/O 경로 | OpenSSL callback/native×서버 인증/상호 인증 4조건과 callback/native zero-loss 외부 metadata 실행을 완료했습니다. 기능 성공과 metric availability, native 빈 stream 해석, 자동 비교 제외를 회귀 시험으로 고정했습니다. 동결 코드의 72×20, 정적 검사, 독립 검토와 normal/external 원자료 감사가 모두 통과했습니다. |
| G011/M7 관측자 영향 | JSON-only `channel_observer` 기본 true 계약, pointer-only on/off, 양 역할의 `handshake_call_begin_to_application_complete` 공통 경계와 독립 CPU availability를 구현했습니다. on/off·off/on·on/off·off/on 네 batch, 16 attempts·32개 역할 파일, 73×20과 원자료 감사를 통과해 완료했습니다. |
| G012 최종 정리 | 최종 cleaner는 NOOP PASS였고 독립 코드·구조 검토, 73×20, 정적 검사와 다섯 보존 원자료 묶음의 offline 재생을 통과했습니다. 수리 전 차단·실패 증거는 별도 보존했습니다. |
| G013 network integrity | 성공 attempt의 여섯 phase 참조에 비어 있지 않은 qdisc 본문과 요청된 trace 본문을 공통으로 요구합니다. N05 baseline의 none/noqueue `limit_packets:null`만 not-applicable로 보존하고 missing/netem-null은 거절합니다. runner와 N05 원자료는 바꾸거나 다시 실행하지 않았습니다. |

## 현재 수치를 해석할 때의 제한

- 기능 시험은 측정값의 정확도나 외부 환경에서의 순위를 증명하지 않습니다. 현재 개발 환경은 WSL이며 클럭·부하를 실험실 조건으로 통제하지 않았습니다.
- 시계 읽기 보정 표본은 연속 계측 읽기의 비용입니다. 사건 추가·스트림 복사·키 로그의 전체 영향까지 포함한 보정값이 아닙니다. 요약은 보정하지 않은 값을 기본으로 합니다.
- 메모리 값은 연결 구간의 라이브러리 요청 힙입니다. 셋업 이후 남아 있는 메모리도 살아 있다면 포함하며 전체 프로세스 메모리나 실제 할당기 내부 순간 최고치와 같지 않습니다.
- 현재 한 역할은 단일 TLS 작업 스레드입니다. 외부 작업 스레드의 연산과 비동기 커널 작업까지 합쳐 센다고 주장하지 않습니다.
- 커널 수신 시각은 별도 원자료입니다. L0 구간 합에 끼워 넣거나 모든 바이트에 대한 정확한 지연으로 변환하지 않습니다.
- 실제 TLS 어댑터의 일부 협상값은 공개 API에서 조회하지 못하거나 고정 허용 목록으로 제한됩니다. 선언과 `incomplete`를 함께 읽어야 합니다.
- 무효 표본은 자동으로 다시 채우지 않습니다. 비정상 종료로 역할 기록이 비어 있으면 `director.txt`에 이유를 남기며 해석기는 완성된 표본인 것처럼 처리하지 않습니다.
- 네이티브 소켓 경로는 진단용입니다. 특히 서버의 첫 수신 경계가 보이지 않아 기본 송수신 구간 보고와 같은 결과를 만들 수 없습니다. 시스템 호출 추적을 붙이기 전에는 기본 경로와의 자동 성능 비교용으로 쓰지 않습니다.
- 합성 조회는 stock TLS Certificate 메시지를 줄이지 않습니다. 조회 원본과 TLS 인증서 입력을 대응시키지만, 조회 결과를 어댑터에 전달해 인증서를 생략하는 구현이 아닙니다.
- netem 설정 loss, qdisc skb drop, TCP 재전송과 조회 경과는 서로 다른 관측입니다. 조회 경과를 순수 RTT라고 부르지 않습니다. offload readback과 packet 관측 한계를 함께 보존합니다.

## 2026년 10월 15일 이후 재개 순서

최신 사용자 요청에 따라 M13·M14는 `docs/mock-ca.md`에 기록된 현재 경계에서 멈춥니다. 이미 보존한 N05 20% loss 64회 증거는 그대로 유지하고 이 범위를 확장하거나 다시 실행하지 않습니다. G007~G013의 후속 요구와 M5·M6·M7 검증을 마쳤습니다. 문서 동결 뒤 최종 milestone commit과 goal metadata 정리는 리더가 수행합니다. M0의 새 작업 폴더 빌드, M1의 소켓 설정·연결 수·격리 시험, M3의 고정 입력 저장·복원 시험을 보완했고 M2의 별도 준비 통로와 파일 원자료 방식은 유지했습니다. 구체적인 실행 결과와 실패도 `docs/validation.md`에 남깁니다.

1. G001~G005는 완료했습니다. G005는 구현, 고정 실제 실행, 해독과 최종 offline report까지 마쳤습니다.
2. G006도 완료했습니다. 전체 57개 시험을 각각 20회 실행해 총 1,140회 통과했고, 최종 정적 검사와 독립 코드·구조 검토를 마쳤습니다.
3. G007의 순수 TLS topology·보고·수명주기 분리·엄격한 원장 읽기와 문서 갱신을 완료했습니다. 최신 전체 58개 시험을 각각 20회 통과했으며 기존 M13·M14의 고정 N05는 확장하거나 다시 실행하지 않았습니다.
4. G008은 139개 경로를 두 Lore 커밋으로 정리하고 각 경계의 독립 반복 증거를 남겨 완료했습니다. 첫 기반 커밋 `cd2a5fa`는 45×20, 최종 커밋 `3723056`은 새 동결 트리에서 58×20을 통과했습니다.
5. G009/M5는 활성 세 어댑터 각각의 client/server와 서버 인증/상호 인증, 모두 12조건을 수정하지 않은 OpenSSL CLI와 검증해 완료했습니다.
6. G010/M6는 구현·독립 검토, 동결 트리의 72×20 반복·정적 검사와 normal/external 원자료 감사를 통과해 완료했습니다.
7. G011/M7은 구현·독립 검토, 실제 4-batch 교대 실행, 73×20과 원자료 감사를 통과해 완료했습니다.
8. G012 최종 cleaner·독립 검토와 전체 회귀·offline 재생을 통과했습니다. G013 shared network integrity 수리도 같은 최종 증거에 포함됐습니다.
9. 현재 사용자 후속 요구와 M5·M6·M7은 완료했습니다. 다만 M10의 eBPF/완전한 패킷·계측 정확도 대조와 M12의 실제 인증서 압축·생략·캐싱 기법 및 원 논문 재현은 구현하지 않은 미래 범위입니다. 메시지 묶음을 개별 메시지 연산 시간으로 나누거나 인증서 경량화 효과를 얻었다는 주장도 하지 않습니다.

## Mock CA·netem 목표의 현재 경계

- 확인됨: config/lookup/transport/capability 5개 대상을 각 20회 반복했고, 원본 PEM을 쓰는 실제 TCP cold/warm 조회가 통과했습니다. service record와 attempt record도 각각 20회 통과했습니다.
- 기존 계약·heap 변경 뒤 전체 45개 시험 단회와 11개 부품 include 경계 검사가 통과했습니다.
- 첫 55개 전체 재검사는 51개 통과, 4개 실패였습니다. 세 조회 통합 시험은 `object_id` 문자열/정수 기대 불일치, 한 기존 교차 파이프라인은 보고 도구 SIGSEGV로 실패했으므로 전체 녹색으로 기록하지 않습니다.
- 이후 57개 단회 전체 검사는 모두 통과했고 생산 번역 단위 21개의 cppcheck·clang-tidy 및 11개 부품 include 경계 검사도 통과했습니다.
- 고정 netem 검증은 일곱 조건 integrity, N05, timeout, warm hit, 명시 loss seed 거절을 모두 증명했습니다. 원자료와 정확한 수치는 `docs/validation.md`에 있습니다.
- 최종 offline report는 보존한 일곱 실행을 다시 처리해 requested=started=100, success=97, timeout=3 및 attempt/connection 행 각 100개를 확인했습니다. 유효 TLS 역할 파일 194개를 모두 해독했고 missing/invalid 6개는 승격하지 않았습니다.
- 최종 20회 반복은 57×20=1,140회 통과, 실패 0건입니다. 최종 정적 검사, 동일 원자료 보고서 재계산, 독립 코드 검토와 구조 검토도 통과했습니다. G001~G006의 요구 증거를 모두 확인했습니다.
- 이후 추가한 순수 TLS netem 시험은 양방향 0ms·20ms, loss 0, 조건별 2 attempts와 역할별 경과·스레드 CPU의 네 그룹을 통과했고 원자료와 최신 parser로 두 번 재생성한 동일 보고서를 `results/followup-tls-netem/pure-tls-preserved/`에 보존했습니다. `check-second.log`의 runner 시작 race 실패도 보존했으며 readiness pipe 수리 뒤 G007 동결 트리의 58개 시험을 각각 20회 통과했습니다. 11개 부품 경계 검사와 24개 생산 번역 단위의 정적 검사도 통과했습니다.
- 이전 PKI matrix 실패 로그는 보존합니다. 공통 유효 기간 수정 뒤 system 3.0·고정 3.5의 9×2와 발급 시각 출력을 240초 앞당긴 shim이 통과해 원인은 수정됐지만, 과거 실패 기록을 삭제하거나 원래 실행의 성공으로 바꾸지 않습니다. shim은 host 시계를 역행시키지 않았습니다.

## 완료 뒤에도 남는 범위 밖 항목

실제 인증서 생략·압축·캐싱 연구 기법, OCSP/ACME 운영 서비스, 스택 최고 사용량, 커널 송신·NIC 시각은 구현하지 않았습니다. WSL에서 얻은 진단 지연과 기능 gate 수치는 물리 Linux의 성능 결론이나 논문 성능 주장으로 사용하지 않습니다. 물리 장비의 perf 정확도와 통제한 성능 실험은 별도 연구 절차가 필요합니다.
