# 네이티브 TLS 응용의 참여 계약

이 문서는 **구현·시험의 인수 기준**이다. 여기에 적은 기능이 현재 빌드에 들어 있다거나 특정 구현이 합격했다는 뜻은 아니다. 역할별 평문 순서와 측정 끝점은 [설계 §4](../DESIGN.md#scenarios)를 따른다.

## 대상에 무엇을 연결하는가

사용자는 측정할 역할과 실행 명령을 지정한다. 앱은 기존 설정 방법으로 TCP 연결, TLS 역할·신원·정책, 송수신 훅을 준비한다. [엔드포인트 SDK](endpoint.md)를 쓰면 앱이 제공하는 것은 이 연결에 대한 핸드셰이크 진행·평문 읽기·쓰기뿐이다. 시나리오 번호에 따라 분기하거나 준비·타임스탬프·내용 검증을 따로 구현하지 않는다. SDK를 쓰지 않는 앱도 아래 표준 입출력으로 이미 수행하는 과업에 참여할 수 있다.

### `native-stream.v1` 실행 접점

- 사용자가 지정한 argv로 네이티브 앱을 직접 기동한다. 셸 명령을 생성하거나 TLS 옵션을 번역하지 않는다. 주소·시험 자격 자료가 필요하면 인자에 공통 자리표시자 `{host}`, `{port}`, `{ca}`, `{cert}`, `{key}`, `{peer_name}`를 쓴다. 옵션 자체는 앱의 기존 CLI 옵션이다.
- stdin은 앱에 줄 평문 바이트, stdout은 앱이 전달한 평문 바이트다(명시된 상속 fd를 쓰는 경우에도 동일). 경계·개행·메타데이터를 평문에 삽입하지 않는다. stderr는 사람용 진단이며 문자열을 파싱해 TLS 성공이나 인증을 선언하지 않는다. 평문과 배너를 분리할 수 없는 앱은 그대로 합격시키지 않는다.
- 호스트가 파이프에서 관찰한 시간과 대상 TLS가 반환한 시간은 다른 지표다. `native-stream.v1`으로 제3 구현의 실제 평문 왕복을 보여도, 대상 측 의미 사건이나 PMU가 없는 시행을 완전한 벤치마크로 승격하지 않는다.

**프로세스 경계는 TLS 원격 호출 규약이 아니다.** SDK는 앱 프로세스 안에서 공개 C 함수를 호출한다. 외부 컨트롤러가 WANT_READ 같은 공급자별 상태를 해석하거나 TLS 호출을 하나씩 RPC로 지시하지 않는다. 제조사 등록, 빌드 시스템 교체, 제조사별 중계기는 요구하지 않는다. 구현체가 지원하지 않는 동작이나 제공하지 않은 지표는 다른 사건으로 대체하지 않는다.

대상은 필요한 경우 원래 실행 경로의 **사건을 한 방향으로 알릴 수 있다**. 이 관찰 경로는 대상에게 다음 TLS 작업을 지시하거나 빌린 소켓의 옵션·수명을 바꾸지 않는다. 새 실행의 완전한 표본에는 **측정 대상**의 실제 송신·수신 훅이 준비부터 측정 끝까지 이어져야 한다. 없거나 중단되어도 확인한 과업 결과와 로컬 평문 반환 시각은 진단 자료로 남긴다. 반대편은 자신의 과업을 확인할 근거만 제공하면 되고 측정 대상의 훅을 대신할 수 없다.

SDK는 준비된 세션에서 시작 동기화를 직접 수행한다. 기존 앱은 `<turtle/start.h>`의 `turtle_wait_start()`로 참여하거나, 같은 시간 네임스페이스에서 양쪽 로컬 `ready`가 첫 TLS 진입보다 앞섰음을 독립적으로 보여줄 수 있다. 해제 시각은 TLS 진입 시각이 아니다. 불참·대기 만료·일방 해제는 완전한 장벽이 아니다.

## 어떤 근거로 무엇을 말할 수 있는가

| 출처 | 허용되는 판단 | 대신할 수 없는 것 |
|---|---|---|
| 응용 입력·출력 | 받은 평문의 내용·길이·순서, 응용 경계에서 관측한 시각 | 대상 TLS 쓰기의 수락, 읽기의 성공 반환 시각, 인증 |
| 대상의 로컬 의미 사건 | 실제 TLS 호출 진입/반환, full-HS 완료, 인증 근거 수락, 평문별 쓰기 시도·수락/읽기 반환·검증. 해당 사건과 역할·연결·메시지 범위가 맞을 때만 사용 | 시작 신호를 TLS 호출 시작으로, 첫 진행을 full-HS 완료로, 검증 근거 수락을 내부 인증 순간으로 간주 |
| 소켓·라이브러리 I/O·헤더 | 각 출처의 실제 바이트 범위와 구간. 소비/수락된 길이만 해당 방향 스트림을 전진시킴 | peek의 중복 바이트, 암호문만으로 인증·호출 성공·평문 검증을 추정 |
| 대상 스레드 PMU | 동일 시행·대상·시작과 끝의 실제 이벤트 ID, raw, enabled/running 근거가 있는 값 | 하네스나 피어의 계수, 추정치 또는 결측을 0으로 채운 값 |

**부재와 반증을 나눈다.** 증거 부재·미계측은 미확인, 명시적 연산 미지원은 미지원, 실제로 확인한 모순은 그 시행 부적격이다. 잘못된 형식은 보고 오류이지 미지원이 아니다. TLS는 설정한 인증 정책을 수행한다. 앱이 인증서 검증 결과를 별도로 보고하지 않아도 시나리오는 실행하지만, 핸드셰이크 성공만으로 인증·협상 지표를 채우지는 않는다. 필수 지표로 지정했다면 해당 근거도 있어야 한다. 확인된 HRR은 1-RTT 표본에서 제외한다.

S2/S4 서버에서 볼 것은 **해당 시행의 선송신 쓰기와 로컬 핸드셰이크 완료 확인**이다. 완료 후 쓰기는 일반 응답일 수 있으나 선송신 표본은 아니다. S2 클라이언트에서는 BIO 도착도, 서버의 쓰기 성공도 아닌 **일반 TLS 읽기의 첫 양수 반환**을 잰다. 같은 연결에서 안내 전체를 확인하고 나중에 로컬 완료를 확인한다. 새 계약의 S2 표본에는 일반 읽기를 첫 연산으로 걸었고 안내 뒤에 로컬 완료를 확인했다는 근거가 필요하다. 읽기 안에서 TLS가 핸드셰이크를 진행하는 것은 위반이 아니다. 먼저 별도 핸드셰이크를 완료하고 읽는 기존 표준 입출력 앱은 실제 첫 반환 시각과 바이트를 남기지만 이 S2 표본에 넣지 않는다.

- 새 실행은 CF 전 도달을 요구하거나 주장하지 않는다. **구형 보관 자료**에 별도 능력 시험이 있을 때만 송신 정지·수신 큐·소비한 암호문 범위로 당시의 주장을 재검산한다.
- 새 S4 표본에서는 CAD의 **마지막 바이트를 수락한 쓰기 반환**이 첫 안내 읽기 반환보다 앞서야 한다. 쓰기를 시도하거나 일부만 수락한 것은 충분하지 않다. 사건 순서만으로 상대 패킷의 도착 순서까지 주장하지 않는다.
- 레코드 경계와 보호 묶음의 의미는 별개다. 양 끝의 실제 full-HS·인증 근거가 없거나 요청과 맞지 않으면 원시 레코드와 그 시각은 보존하되 보호 묶음의 내부 구성원은 명명하지 않는다. 헤더 콜백 역시 완전하다고 가정하지 않는다. 비교 가능한 바이트 범위에서 누락이 드러나면 헤더 전체를 계측했다는 주장을 받아들이지 않으며, 독립 소켓 관측은 유지한다.

## 고정 인수표

아래 번호는 d028c2d 독립성 리뷰의 반례와 일대일 대응한다. 성공 사례만 돌리는 것으로 이 표를 대체할 수 없다.

| ID | 통과 조건 |
|---|---|
| H1 | 코어와 공통 소비자(실행 파일·입출력 규약)를 먼저 고정하고 해시를 기록한다. 이후 독립 빌드한 제3의 실제 TLS 응용이 **기존 중립 인터페이스**로 같은 소비자에 참여한다. 등록·재링크·제조사별 shim/설정 변환 없이 실제 평문과 판정 가능한 범위 및 결측을 보인다. 모든 지표에 합격했다는 증거와는 별도다. |
| H2 | reference 없이 코어를 빌드·설치할 수 있고, reference를 켜도 기본 빌드·설치에 제조사별 DUT 드라이버가 없다. |
| H3 | 확인된 HRR을 basic 결과에도 보존하고 1-RTT 표본에서 제외한다. 미관측을 HRR 없음으로 바꾸지 않는다. |
| H4 | 일반 S2/S4에서 완료 후 안내가 확인된 시행은 탈락한다. 구형 능력 시험의 양성 결과도 이 순서를 대신하지 못한다. 온라인 판정과 재분석이 같다. |
| H5 | 준비부터 측정 끝까지 전송 훅이 연속이어야 전체 계수로 인정한다. 중도 해제 후 양수 잔여값은 불완전이며, 상세 사건이 있으면 실제 시도/양수 수신 수와 대조한다. |
| H6 | 빌린 fd의 TCP_NODELAY·timeout·소유권이 attach 전후 같다. 생성한 소켓의 기본 설정과 구분한다. |
| M1 | 바이트, 레코드 배치, 실제 구간 시각, 이름 붙은 필수 보호 묶음을 각각 판정한다. 상세 모드 요청만으로 가용 판정을 내리지 않는다. |
| M2 | 표시 이름 대신 표준 협상 ID를 비교한다. P-256 별칭은 일치하며, 검증된 SH·피어 등 근거끼리 모순되면 수락하지 않는다. |
| M3 | 실제 빌드의 해당 송신 방향 padding 정책·평문 길이·암호문 범위가 입증된 방향만 분류한다. 반대 방향의 결측으로 입증된 방향을 지우지 않는다. 보호 묶음 내부를 임의 분해하지 않는다. |
| M4 | capability의 false와 누락·null·형식 오류가 다른 판정을 낸다. |
| M5 | MSG_PEEK 뒤 실제 recv가 같은 바이트를 돌려줘도 양수 반환 횟수와 소비 오프셋이 구분된다. |
| M6 | 소켓 구간·라이브러리 I/O·헤더 관찰을 독립 제공하거나 조합할 수 있다. 각각 실제 출처를 보존하며 앱의 전송 경로를 교체하지 않는다. |
| M7 | 첫 HS 진행, full-HS 성공, 인증 근거 수락을 구분한다. CAD/SAD₁/SAD₂마다 첫 쓰기 시도·최종 수락·첫/마지막 읽기·전체 검증 사건을 역할별로 식별하고 누락된 사건은 그 메시지에서만 결측 처리한다. |
| L1 | 단측 실행에서 지정한 상대를 우선하며 생략 시에만 기본 피어를 쓴다. 상대를 명시해도 측정 역할은 하나다. |

제3 구현 인수에는 사전에 고정한 소비자·코어와 실제 외부 TLS 실행 파일(예: GnuTLS CLI)을 사용한다. 시험 환경에서 선택적으로 생략한 통합 시험은 릴리스 증거가 아니다. 릴리스 검증은 해당 실행 파일을 필수 fixture로 요청하고, 없거나 실제 교환이 실패하면 통과시키지 않는다.

검증 기록에는 고정한 산출물, 실행 명령·버전, 원자료 식별자와 판정 이유를 남긴다. 두 역할 × 두 인증 방식 × S0–S4의 각 셀을 보고하고 예열·진단, 구형 자료의 별도 능력 시험은 본 표본에 넣지 않는다. 하드웨어 계수·물리 보드 실측이 없으면 이를 시험 성공으로 발표하지 않는다.
