# 보고서와 비교

`python3 scripts/report.py INPUT OUTPUT`은 새 실행 한 쌍 또는 `study.json`에 명시된 실행들을 읽습니다. 임의의 하위 디렉터리에서 구형 결과를 찾아 합치지 않습니다. 출력은 `turtle-message-report/1`의 JSON과 연결별 CSV입니다.

클라이언트와 서버를 분리하고, 같은 프로세스·컨텍스트를 독립 표본 한 개로 취급합니다. 연결 위치별로 서로 다른 컨텍스트의 분포를 만듭니다. 준비 연결, 실패한 실행, 재사용 연결을 독립 성공 표본으로 섞지 않습니다. 컨텍스트 대표값은 해당 컨텍스트의 측정 연결들에서 StQ2를 먼저 구한 별도 기술통계입니다. 반복 연결 수를 독립 표본 수로 바꾸지 않습니다.

준비, 연결별 프로토콜 비용과 첫 사용 비용을 함께 보존합니다. 서버의 수신 소켓 준비(listener_preparation_ns)도 최초 준비에 한 번 포함합니다. 클라이언트는 수신 소켓을 만들지 않으므로 이 항목의 실제 비용이 0입니다. 필수 준비 사건이나 연결별 TCP 측정이 누락되면 첫 사용 비용은 null이며, 관측하지 않은 구간을 0으로 대신 더하지 않습니다. 첫 사용 값은 실제 첫 연결에만 있습니다. 준비 연결이 있다면 그 첫 연결이 첫 사용이며 첫 측정 연결로 옮기지 않습니다. 두 번째 연결 이후에는 컨텍스트 준비 비용을 더하지 않습니다. White-box의 하위 비용은 transition, assemble, process, protect, unprotect, send, receive, wait, verify의 서로 겹치지 않는 구간만 합칩니다. 나머지는 프레임워크 실행·계측 비용으로 별도 표시합니다. 메시지·레코드 관계와 배치 부모 시간을 다시 더하지 않습니다. 메시지 행의 direct_stage_costs는 그 메시지의 조립·처리·전환 비용만 담습니다. 공유 암복호화 비용은 레코드 행의 operation_ns에 한 번만 있으며 메시지 행은 레코드 ID를 참조합니다. BEGIN·FINISH의 연결 전체 전환은 임의의 메시지에 붙이지 않습니다.

StQ1·StQ2·StQ3는 정렬한 경험 분포의 각각 [1/8,3/8], [3/8,5/8], [5/8,7/8] 구간을 평균한 값입니다. 순위 구간에 걸친 값에는 정확한 분수 가중치를 사용합니다. 원시 시각의 차이는 정수로 계산하고 요약값만 실수로 표시합니다. 작은 표본의 이 요약이 정상성이나 충분한 표본 수를 보장하지 않습니다.

탐색 비교는 같은 배치·상대 구현체·역할·연결 위치·시나리오·인증·그룹·인증서·계측·레코드·송신·조회·네트워크 조건끼리만 만듭니다. 구현체별 독립 컨텍스트가 최소 두 개 있어야 합니다. 저장한 seed로 컨텍스트를 다시 뽑아 StQ2 차이의 백분위 구간을 계산합니다. 기본 재표집 수는 1000입니다. 실패·누락·아직 실행하지 않은 항목이 있는 배치, 별도 CPU 수집 실행, 할당 관측이 누락된 실행은 비교 적격 상태로 만들지 않습니다. 이는 탐색 결과이며 가설 검정이나 성능 우열 결론이 아닙니다.

이 조건 대조는 `report.py`의 `CONDITION` 필드와 구현체·상대 이름에 한정됩니다. 빌드·바이너리 해시, `io_chunk`, `max_message`, `event_capacity`, 완전한 호스트 조건과 외부 관측 보고서의 실제 가용 판정을 자동 대조하지는 않습니다. 해당 설정·출처 파일을 따로 확인해야 하며 `exploratory`를 모든 조건의 동일성 인증으로 읽지 않습니다. 여러 연결 위치를 함께 재표집한 공동 곡선도 아닙니다. 비교 조건을 연구 계획에서 선언하는 제안은 [설계 논의](../design/discussion.md)에 있습니다.

```sh
python3 scripts/study.py examples/message/study.json --output results/study
```

study 계획은 `turtle-message-study-plan/1`이며 seed, batches, samples, cases와 공통 options를 지정합니다. 매 배치 안에서 조건·반복의 실행 순서를 섞고 **실행 전에 전체 순서**를 저장합니다. 각 표본은 양쪽 엔드포인트의 새 프로세스입니다. 실패 사유와 scheduled/running/complete/failed 상태를 원장에 남깁니다. BiTHaC처럼 양쪽 구현체를 함께 바꾸는 self-pair 결과는 양쪽 엔드포인트 조건이 달라집니다. 자동 비교기가 이를 상대를 고정한 비교인 것처럼 합치지 않으며 각 조건의 분포를 따로 제공합니다.
