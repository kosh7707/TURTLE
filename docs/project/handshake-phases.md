# 핸드셰이크 네 구간의 관측과 해석

TURTLE은 ClientHello, ServerHello, 서버의 (EncryptedExtensions, Certificate, CertificateVerify, Finished) 묶음, 클라이언트 Finished를 클라이언트와 서버 각각에서 관측합니다. 핸드셰이크 내부 상태를 계측하는 기능은 아니며 라이브러리 수정·복호화·핸드셰이크 메시지 콜백을 요구하지 않습니다.

## 구간 식별의 근거

공개 `turtle_handshake_info.profile`에 `TURTLE_PROFILE_SERVER_AUTH_1RTT`를 선언한 성공한 엔드포인트 쌍을 분석합니다. 구현자는 현재 설정이 인증서 기반 서버 인증이고 클라이언트 인증·재개·0-RTT·HRR·핸드셰이크 호출 중 티켓과 응용 데이터가 없음을 보장합니다. 호환용 CCS는 허용합니다. 프로파일은 구현자의 선언이며 암호문 내용을 검사한 결과가 아닙니다. 설정 소스나 연산을 바꿀 때 이 선언도 유지 가능한지 확인해야 합니다.

실제 송신 스트림에서 공개 handshake 호출에 속한 레코드를 찾습니다. 평문 type 22 레코드의 본문을 이어 ClientHello 또는 ServerHello의 4바이트 핸드셰이크 헤더, 종류, 길이를 확인합니다. 헤더와 메시지가 여러 레코드로 나뉘어도 처리하며, 알려진 HRR random이 있으면 이 프로파일의 구간 분석을 완료하지 않습니다. 이는 정상 프로토콜 흐름의 지원 범위를 정하는 검사입니다.

서버의 성공한 handshake 호출에서 송신한 type 23 레코드 전체를 서버 암호화 묶음, 클라이언트의 같은 범위를 클라이언트 Finished로 연결합니다. 의미는 위 프로파일과 성공한 공개 호출에 근거하며 암호화된 개별 메시지를 확인하거나 분리한 것이 아닙니다. 원래 TLS 레코드와 핸드셰이크 메시지는 일대일 관계가 아니므로 고정 레코드 번호를 사용하지 않습니다. [RFC 9846 로컬 사본의 2절과 5.1절](../references/rfc9846.txt)

송신에서 찾은 실행·연결·방향·레코드 키와 바이트 범위가 상대의 수신 handshake 호출에도 완전히 포함되는지 확인합니다. 소켓 사건이 관측 구간 경계를 가로질러 끝 시각을 나눌 수 없거나 필요한 범위가 없으면 `phase_complete=false`로 기록합니다. 미완료 이유와 기존 TLS 시나리오 성공 여부는 별도입니다.

## 시간 경계

| 구간 | 시작 | 끝 |
|---|---|---|
| ClientHello | handshake 호출 진입 | 이 엔드포인트에서 ClientHello 마지막 바이트를 처리한 소켓 호출 반환 |
| ServerHello | ClientHello 구간 끝 | 이 엔드포인트에서 ServerHello 마지막 바이트를 처리한 소켓 호출 반환 |
| 서버 암호화 묶음 | ServerHello 구간 끝 | 이 엔드포인트에서 서버 묶음 마지막 바이트를 처리한 소켓 호출 반환 |
| 클라이언트 Finished | 서버 묶음 구간 끝 | handshake 호출 반환·성공 확인 |

`interval_wall_ns`와 `interval_thread_cpu_ns`는 이 경계 사이의 실행 비용입니다. 각 표본에서 네 구간의 합이 전체 공개 handshake 호출과 정확히 일치해야 합니다. 클라이언트와 서버는 각자 로컬 시계로 계산하며 서로의 시각을 빼지 않습니다. CPU는 호출 스레드의 비용입니다.

선택적 perf 카운터도 `interval_event_boundaries`의 시작·끝 사건 ID를 참조합니다. 네 구간의 원시 cycles·instructions·그룹 활성/실행 시간 합을 전체 핸드셰이크와 대조합니다. 별도 perf CPU 표본은 같은 단조 시각의 반열린 구간에 배정하고 네 구간 표본 수의 합을 전체 핸드셰이크 표본 수와 대조합니다. 이는 메시지 내부 함수 경계를 추가 관측한 것이 아닙니다. [수집과 보고서의 구분](perf.md)을 참고합니다.

구간 이름은 내부 연산의 귀속을 뜻하지 않습니다. 예를 들어 OpenSSL의 한 송신 콜백에 ServerHello와 서버 암호화 묶음이 함께 들어가면, 암호화 묶음까지 미리 만든 계산이 ServerHello 구간에 포함될 수 있습니다. 클라이언트가 서버 묶음을 받은 뒤 수행한 검증과 Finished 준비는 클라이언트 Finished 구간에 들어갈 수 있습니다. 내부 메시지 생성·검증 비용은 `unsupported`로 남깁니다.

`io_span_*`는 해당 구간의 첫 바이트 관련 소켓 호출 진입부터 마지막 바이트 관련 호출 반환까지입니다. 그 사이의 처리와 대기를 포함할 수 있습니다. `socket_*`는 관련 소켓 사건을 한 번씩 더한 값입니다. 이 두 지표와 `interval_*`는 서로 겹치므로 합산하지 않습니다. 클라이언트 Finished의 마지막 바이트 처리 시각과 공개 handshake 완료 시각도 원자료에서 각각 보존합니다.

`interval_socket_*`는 주 관측 구간의 시간 범위에 들어가는 모든 소켓 호출 비용이며 CCS의 소켓 대기도 포함합니다. 이 값도 구간 시간의 일부입니다. 각 표본에서 네 구간의 이 지표를 더하면 전체 handshake 안의 소켓 호출 시간 합과 정확히 같습니다. 메시지 바이트만 연결한 `socket_*`와 범위가 다르므로 사람이 읽는 시간 표는 `interval_socket_*`를 사용합니다.

## 공유 비용과 호환용 CCS

각 전송 콜백의 실제 바이트 범위가 어떤 구간과 연결되는지 사건 ID로 보존합니다. 하나의 콜백이 여러 구간에 걸쳐도 전체 비용을 각 구간에 복사하지 않습니다. `exclusive_frame_*`에는 하나의 구간에만 연결되는 직접 프레임 사건만 들어갑니다. 공유·CCS·연결할 수 없는 프레임 사건 비용을 별도로 보존하며 이들과 전용 비용의 합을 전체 프레임 사건 합과 대조합니다.

handshake 진입부터 첫 전송 콜백 진입, 콜백 반환부터 다음 콜백 진입, 마지막 반환부터 handshake 완료까지의 모든 구간을 `outside_transport_intervals`에 저장합니다. 전송 콜백 시간 합과 이 구간 합은 전체 핸드셰이크와 정확히 같습니다. 앞뒤 전송 ID와 관련 구간을 함께 보존합니다. 이 실행에는 입력 처리·출력 준비·공개 호출 및 기록 경계의 비용이 포함될 수 있으며 순수 암호 계산으로 부르지 않습니다.

`handshake_before_shared_send_gap_*`는 서로 다른 주 구간의 바이트를 함께 보내는 전송 호출 직전의 콜백 밖 구간 합입니다. 내부 계산을 따로 나누기 어려운 위치를 보여주는 지표입니다. 이 값이 0이면 해당 관측 형태가 없었다는 뜻이며 암호 계산 비용이 0이라는 뜻이 아닙니다.

type 20, 본문 1인 호환용 CCS는 `auxiliary`에 따로 기록합니다. 그 바이트를 Hello나 Finished 크기에 섞지 않습니다. CCS 때문에 소켓에서 기다린 시간은 실제 시간축에서 위치한 주 구간에 남습니다. 네 구간 시간의 전체 합은 유지하면서 바이트의 의미를 구별하는 방식입니다.

## 네트워크와 반복 집계

각 구간의 프레임 범위와 TCP 패킷 페이로드의 교집합을 계산합니다. 패킷 하나가 여러 구간과 겹치거나 프레임 헤더가 없는 일부 바이트만 재전송되어도 해당 바이트만 각 범위에 연결합니다. 재전송은 그 방향의 송신 엔드포인트 캡처에서만 집계합니다. 양쪽 역할의 구간 행은 같은 관측을 참조하므로 역할별 값을 합산하지 않습니다.

구간별 TLS·프레임·추가 바이트, 레코드 수, 송신 캡처 페이로드·재전송 바이트와 두 캡처의 패킷 ID를 보존합니다. 캡처 미수집과 누락을 실제 0으로 바꾸지 않습니다. 캡처가 없어도 로컬 구간 시간은 유효할 수 있습니다.

`report.json`의 `phase_metrics`와 `phase_report.csv`에 구성·역할·구간·지표별 전체 시도, TLS 성공, 상세 계측 성공, 유효 표본 수, 가용성별 개수, 중앙값·Q1·Q3·IQR, 기준 중앙값 차이와 독립 프로세스 표본 부트스트랩 95% 구간을 제공합니다. `sample_sum`은 유효 표본 값의 합이며 재전송 총량에 사용합니다. 레코드를 독립 표본으로 재추출하지 않습니다.

`report.md`와 `report.html`은 같은 집계로 자동 생성합니다. 전체 비용, 네 구간의 벽시계·CPU·소켓 비용, 구간별 바이트·재전송, 공유 실행 구간과 무효 이유를 포함합니다. 원자료 해석과 보고서 생성은 Python 표준 라이브러리만 사용합니다.

## 형식과 기존 실험

프로파일을 기록하는 엔드포인트는 `turtle.endpoint.v3`입니다. 측정 사건은 바뀌지 않은 `turtle.event.v2`를 사용합니다. 상세 분석은 `turtle.attempt-report.v3`, 비교 보고서는 `turtle.comparison.v3`입니다. 프로파일이 없는 이전 엔드포인트 형식을 추정해서 읽거나 과거 결과에 새 의미를 소급해서 붙이지 않습니다. 이전 원자료와 보고서는 보존하고 새 바이너리로 새 시도를 실행합니다.
