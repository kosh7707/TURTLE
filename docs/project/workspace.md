# 작업 공간과 자료 보존

2026-11-16에 반복 빌드와 구형 빌드 경로를 정리했습니다. 활성 소스·빌드, 재현 입력, 실행 원자료, 과거 검증 자료의 수명을 구별합니다.

## 활성 경로

| 경로 | 역할 |
|---|---|
| `include/`, `src/`, `implementations/`, `cmake/` | 현재 소스 계약·실행 코드·native 경계·빌드 등록 |
| `scripts/`, `tests/`, `examples/`, `docs/` | 현재 실행·검증·예제·설명 |
| `build-message/` | 현재 엔드포인트·코어·커널 관측기 빌드 |
| `build-message-tests/` | 별도 시험 빌드와 이번 시험의 evidence |
| `.deps-message/` | 현재 고정 소스에 패치를 적용한 의존성 빌드 |
| `.deps/downloads/` | 고정 배포본 캐시 |
| `.deps/src/bithac`, `.deps/src/wolfssl-5.8.2-stable` | 오프라인 추출에 필요한 고정 git 객체와 원본 저장소 |
| `.deps/src/libbpf-headers-1.6.3` | 커널 관측기 빌드용 고정 헤더 |
| `.deps/tools/perf`, `.deps/manifests/perf-tools.json` | 실제 CPU 수집 도구와 출처 |
| `pki/`, `results/` | 시험 자격 증명과 실행 당시 자료 |

`build-message/`만 지우고 의존성을 다시 받을 필요는 없습니다. 반대로 `.deps/downloads`·필요한 git 객체를 지우면 깨끗한 디렉터리에서의 오프라인 의존성 빌드를 할 수 없습니다. native 패치가 바뀐 경우에는 별도의 빈 의존성 경로를 사용합니다. 현재 경로의 재사용 여부는 `dependencies.py`의 출처 검사에 따릅니다.

## 2026-11-16 정리 내역

[정리 원장](../../artifacts/maintenance/2026-11-16/manifest.json)에 이동한 경로, 제거한 생성물, 보존 자료 확인 결과가 있습니다. [일회성 정리 스크립트](../../artifacts/maintenance/2026-11-16/cleanup.py)와 실행 로그도 같은 위치에 보존했습니다. 이 스크립트는 당시의 경로를 대상으로 한 기록이며 일반적인 정리 명령으로 다시 실행하지 않습니다.

루트의 활성 빌드는 `build-message`와 `build-message-tests`만 남겼습니다. 이전 `audit`, `clean`, `complete`, `release`, `offline`, `cachefix` 등 반복 빌드, 구형 모듈 빌드와 개발 중의 native 스냅샷은 [빌드 이력](../../artifacts/build-history/2026-11-16)에 모았습니다. 그 안에서 재생성 가능한 CMake/Ninja 캐시·오브젝트·정적 라이브러리·실행 파일과 중복 native 빌드를 제거했습니다. 구형 의존성 설치물과 `.vs`, Python 바이트코드 캐시도 정리했습니다.

제거한 생성물은 85,469개 파일, 논리 크기 7,731,282,270바이트(약 7.2GiB)입니다. 이는 파일 길이의 합이며 파일시스템에서 실제 회수한 블록 수나 WSL 가상 디스크 축소량을 뜻하지 않습니다. source snapshot과 메타데이터 중 역사적 변경을 설명하는 자료는 보존했습니다.

2026-11-13의 최종 오프라인 검증은 [build-message-final](../../artifacts/build-history/2026-11-16/build-message-final)에 의존성·바이너리·시험 자료까지 통째로 보존했습니다. 이 디렉터리의 CMake 캐시는 당시 절대 경로를 담고 있으므로 현재 활성 빌드로 사용하지 않습니다. 새로운 빌드는 README의 활성 경로나 별도의 빈 경로에서 만듭니다.

나머지 과거 빌드에서도 실행 원자료·보고서·검증 원장·로그·시험 PKI와 의존성 출처를 보존했습니다. 보호한 자료 트리는 이동 후 정리 전후의 상대 파일명·inode·길이·수정 시각을 대조했습니다. 내용은 다시 쓰지 않았습니다. `results/`의 기존 실행 자료와 `docs/references/`의 참고 문헌도 유지했습니다.

## 이후의 정리 기준

현재 문서는 활성 경로를 안내합니다. 검증 문서는 실행 날짜와 당시 자료의 보존 위치를 안내합니다. 원자료 안의 오래된 절대 경로는 당시 출처의 일부이므로 수정하지 않습니다. 이동 원장으로 원래 위치와 보존 위치를 연결하며 호환 판독기나 심볼릭 링크 별칭을 만들지 않습니다.

새 실험은 새 출력 디렉터리를 사용합니다. 유지할 검증 실행을 고른 뒤 원자료·실행 명세·출처·필요한 바이너리·심볼을 보존하고 반복 빌드의 생성물을 정리합니다. CPU 표본의 보존 바이너리·심볼과 pcap·스트림은 단순한 빌드 캐시로 분류하지 않습니다. 고정 원본 캐시, 시험 PKI, 과거 실험 자료는 빌드 파일과 별도의 보존 판단이 필요합니다.
