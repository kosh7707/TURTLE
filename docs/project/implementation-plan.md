# TURTLE 독립 엔드포인트의 구현 범위

2026년 11월 12일의 후속 로컬 실험 웹·저장소 정리 요청과 결과는 [로컬 웹·재현 기록](local-web-reproduction.md)을 따릅니다. 아래 독립 엔드포인트 계약은 유지하며 웹은 별도 로컬 저장소에서 기존 원자료·보고서를 읽습니다.

2026년 11월 12일의 최신 요청을 기준으로 합니다. 목표는 클라이언트와 서버의 독립 빌드·배포·실행·계측과 WSL에서 가능한 정상 TLS 기능 검증입니다. SSH 자동화보다 IPv4:Port 접속과 시험 준비 확인을 우선하며, TLS 원자료는 schema 3만 판독합니다. 실행·설정·분석의 과거 호환 경로는 유지하지 않습니다.

## 현재 실행 계약

- `turtle-client`, `turtle-server`, 분석 도구를 따로 구성합니다. 빌드 폴더·툴체인·의존성 경로를 각각 선택하며 교차 컴파일 호스트에서 대상 프로그램을 실행하지 않습니다.
- 기본 `builtin`은 어댑터 하나를 실행 파일에 연결합니다. `module`은 지정한 공유 모듈만 읽습니다. 공개 `ImplementationApi` ABI 3은 같고 TLS 라이브러리 자체의 정적·동적 링크는 별도 출처입니다.
- 서버는 `--listen`·`--control-listen`, 클라이언트는 `--connect`·`--control-connect`에 숫자 IPv4:Port를 지정합니다. `0.0.0.0`은 수신 주소이며 접속 대상으로 사용하지 않습니다.
- 별도 TCP 제어 프로토콜 2에서 실행·컨텍스트 ID, 공유 시나리오와 양쪽 준비 상태를 확인합니다. 제어 포트 접속, TLS 컨텍스트·버퍼 준비, 실제 데이터 연결·인증 성공을 구별합니다. 확인용 TLS 연결 없이 첫 측정 연결을 보존합니다.
- 엔드포인트는 자기 파일·CPU·소켓·계측기만 소유합니다. TLS 연결→컨텍스트→지원 서비스·모듈 순으로 정리합니다. 같은 시한을 재시도에 사용하며 상대의 절대 단조 시각을 전달하지 않습니다.
- 기본은 프로세스당 컨텍스트 하나, 워밍업 0회, 측정 연결 1개입니다. 독립 표본은 외부 실행기가 새 프로세스로 반복합니다. 명시적 컨텍스트 재사용과 실패 구간·이유·부분 원자료를 보존합니다.
- TLS schema 3의 측정 계약 개정 3·4를 받으며 새 실행은 개정 4를 기록합니다. `end_sequence`로 측정 종료를 찾고 선택한 양쪽 파일을 실행 ID로 연결합니다. 교차 장비 단조 시각은 직접 빼지 않습니다. 서비스·원장·해독·네트워크 자료의 schema는 독립적입니다.
- 로컬 실행기가 프로세스·시도 원장을, netem 실행기가 네임스페이스·veth·관측기를 소유합니다. 관측용 로컬 소켓은 netem 실행에만 만들고 준비·정리 경계에서 사용합니다. TLS 데이터와 제어·조회 흐름을 구분합니다.

검증 결과와 실제 실행 명령은 [검증 기록](validation.md)에, 현재 확인 범위를 모은 문서는 [구현 보고서](implementation-report.md)에 둡니다. 이전 구조의 시험 수·성능 표를 현재 결과에 합치지 않습니다. 관찰 결과로 바꾼 계약과 이유는 [결정 기록](DECISIONS.md)에 남깁니다.

## 완료 범위와 후속 작업

계측 의도 대조 작업은 정상 TLS 성공, 계측 근거, 보고 적격성을 따로 검증합니다. 최신 합의에 따라 새 실행의 종료는 마지막 TLS API 성공 반환이며 측정 계약은 개정 4입니다. 기준선·실패 로그·개정 3 원자료를 보존하고, 결정적 사건열과 실제 세 라이브러리의 내장·모듈 조합을 대조합니다. 확인한 오류와 환경 때문에 수행하지 못한 항목은 [검증표](validation.md#계측-의도와-실제-동작의-대조)에 남깁니다. 정상 TLS 시험 통과를 계측 전체의 정확성 증명으로 확대하지 않습니다.

이번 완료 판정은 독립 엔드포인트 구조와 로컬 기능입니다. 지원 불가·미관측·해당 없음·누락·실제 0을 구별하고 PMU 계수를 시간 환산값으로 대체하지 않습니다. `builtin`의 모듈 로드는 해당 없음이며 프로그램 진입 전 로더 비용은 측정하지 않습니다.

실제 ARM 툴체인·장비 검증, 물리 NIC 경로, 네이티브 Linux 본 성능 실험, 배포 크기·RSS 계측은 미검증입니다. 배포·프로세스 재시작·결과 회수는 외부 실행 환경의 책임이며 SSH 자동화는 필수 후속 항목이 아닙니다.

전체 연구 완료에는 장비별 관측 부담 평가와 반복 수·컨텍스트·캐시·네트워크·주 지표·통계의 동결이 더 필요합니다. BiTHaC 논문의 정확한 timer 경계와 일부 최적화는 미확정·미지원이며, ML-KEM C/AVX2 비교를 AVX-512 후보 논문의 재현으로 표시하지 않습니다. 강건성·공격·인증서 거절·타이밍 누출 시험은 범위 밖입니다.
