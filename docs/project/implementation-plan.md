# TURTLE 구현 계획과 현재 통과 범위

2026년 11월 11일 사용자 계획을 기준으로 합니다. OpenSSL 프로토타입 → wolfSSL 적용 → Mbed TLS 적용 → 논문 기법 → TCP·CPU 분석 → 본 실험·ARM 재현 순서로 진행합니다. 프로토타입의 기능 통과와 전체 연구 완료는 구별합니다.

| 단계 | 현재 산출물 | 남은 통과 조건 |
|---|---|---|
| 0. 기준선 | 세 고정 라이브러리 빌드, 기존 시험, 별도 소스·시험 빌드, 정적 검사 | 네이티브 Linux의 성능 카운터·커널 추적 지원 재확인 |
| 1. OpenSSL 프로토타입 | 시행별 새 TCP, 네 시나리오, 두 송신 정책, 실제 내부 작업 패치, 기록·보고 | 본 실험 장비의 관측 부담 평가 |
| 2. wolfSSL 적용 | 서버 Ping, Hello 포함 처리, 레코드·I/O 전 생성 구간, 넓은 송신 구간, 회귀 시험 | 생성에 포함되는 준비·평문 헤더 비용의 구현별 차이를 보존 |
| 3. Mbed TLS 적용 | 조기 Ping, Hello·확장·CertificateRequest·인증서·CertificateVerify·Finished 바디 생성과 fetch 뒤 처리, 회귀 시험 | 바디 밖의 준비·마무리 비용을 독립 메시지 생성 비용으로 합치지 않음 |
| 4. 논문 기법·구현 최적화 | 저자 BiTHaC 같은 커밋의 캐시 끔/켬 쌍, ML-KEM-768 동일 기반 C/AVX2 쌍, 실제 호출 분기·정상 벡터·인증·응용 교환, 시간/추적/메모리 분리와 표 재생성 | BiTHaC 논문 원래 측정 구간의 정량 대조, 미채택 AVX-512 후보와 혼동하지 않는 해석 |
| 5. TCP·CPU | pcap·TLS/TCP 바이트, TX_SCHED/TX_SOFTWARE/TX_ACK, 속도·초기 cwnd·TCP_INFO, 지정 바이트 최초 손실·실제 qdisc 제거·커널 재전송, perf.data·함수/모듈 비중 | 네이티브 환경에서 관측 부담·도구 호환성 재확인 |
| 6. 본 실험·ARM | 실행·분석 절차와 미완료 조건 | 장비 확보, 예비실험 뒤 조건·통계 동결, 네이티브 Linux 본 실험과 ARM 재현 |

사용자는 현재 네이티브 Linux·ARM 장비가 준비되지 않았다고 확인했습니다. WSL에서 가능한 구현·기능 검증을 진행하며 본 성능 실험으로 표시하지 않습니다. 라즈베리파이 준비는 ARM 반복 단계에서 수행할 수 있습니다. 장비 부족과 미완료 소프트웨어 작업은 별개입니다.

## 현재 임시 실험 기준

사용자의 후속 요청에 따라 네이티브 Linux·ARM 단계는 나중으로 두고 로컬 실제 TLS 실험을 진행합니다. TLS 엔드포인트는 클라이언트·서버 프로세스 두 개이며, 현재 구현된 클라이언트·라우터·서버 네트워크 네임스페이스와 veth 두 쌍을 기본으로 유지합니다. 라우터는 커널 포워딩이며 별도의 TLS 상대가 아닙니다. 실행 조정·네임스페이스 유지·관측용 보조 프로세스는 엔드포인트 수와 구별합니다.

시행마다 새 TCP 연결 하나로 양방향 TLS·응용 교환을 수행합니다. 서버의 수신 대기 포트 하나와 클라이언트의 임시 포트를 사용하며 방향별 실험을 위해 수신 대기 포트 두 개를 추가하지 않습니다. netem은 라우터의 수신자 방향 출구에 각각 두어 `tls_c2s`와 `tls_s2c`를 독립적으로 제어합니다. 조건은 시행 시작 전에 고정하고 무지연·클라이언트→서버 지연·서버→클라이언트 지연·양방향 지연을 별도 실행합니다. 예시는 `examples/networks/tls-{no-loss,c2s-delay20,s2c-delay20,both-delay10}.json`입니다.

Docker 도입은 이 로컬 실행의 선행 조건이 아닙니다. 현재 이름공간·veth 실행기의 관측과 정리 절차를 사용합니다. WSL의 결과는 계속 개발·기능 자료로 구분합니다.

관리자 권한에서 지정 손실 tc/eBPF와 커널 수집기를 실제 실행기에 연결했습니다. `artifacts/kernel-loss-matrix-final/verification.json`의 세 라이브러리·다섯 조건·60개 TLS 연결에서 실제 제거 범위, 재전송 복구, 인증·응용 교환, 관측 누락 0과 정리를 검증했습니다. 일반 실행은 기존 user namespace 격리를 쓰고, 커널 관측을 요청한 실행만 initial user namespace의 root로 수행합니다. 이 권한 차이는 비교 조건에 남깁니다.

## 잠정 계약

공개 ABI 3, TLS 원자료 schema 2, 측정 계약 개정 3을 사용합니다. schema 1의 기존 뜻은 보존하며 보고서는 기존 자료도 읽습니다. 이후 의미나 ABI가 바뀌면 해당 버전을 올리고 영향받은 자료를 다시 수집합니다.

실행은 `모듈 로드 → 컨텍스트 셋업 → 시행 준비 동기화 → 새 TCP → 연결 객체 준비 → TLS·응용 → 연결 정리`입니다. 서버 accept 대기, 클라이언트 TCP 연결, 연결 준비, API 완료, 내부 Finished와 응용 구간을 나눕니다. 같은 컨텍스트의 연결 위치는 종속 관측이며 첫 측정 연결을 버리지 않습니다. 기본은 컨텍스트당 연결 1개, 워밍업 0회입니다.

네 시나리오는 `handshake`, `server-ping`, `finished-ping`, `client-request`입니다. 양 방향 크기를 독립적으로 정하고 기본은 각각 32바이트입니다. `native`와 `server-hello-first` 정책은 추적 모드와 독립입니다. Finished와 Ping은 TLS 레코드·키 경계를 유지한 출력 배치로 묶습니다. 버퍼 수용과 소켓 제출을 구별하며 TCP 세그먼트 수는 보장하지 않습니다.

## 실제 적용에서 반영한 피드백

- wolfSSL의 `SendTls13*` 전체는 `library_message_write`입니다. 추가한 스택 소유 생성 구간은 레코드·입출력 전에 닫으며 인증서 조각별 생성도 따로 기록합니다. 두 구간을 더하지 않습니다.
- Mbed TLS 바디 생성 밖의 준비 비용은 별개입니다. Finished를 먼저 flush하고 응용 키 순번을 보존해야 정상 Ping을 보낼 수 있었습니다.
- BiTHaC의 wolfSSL 5.7.0은 서버 조기 응용 쓰기 조건이 5.8.2와 달랐습니다. 양 비교 구현에 같은 실행 지원 패치를 적용하고 논문 캐싱 코드와 구별했습니다.
- 모듈 로드나 설정만으로 기법 사용을 추정하지 않습니다. 실제 캐시 인증서 송신 함수 사건과 해독한 Certificate 바이트를 함께 확인합니다.
- ML-KEM 비교에서는 두 관련 C 소스만 컴파일 분기가 다르고 다른 라이브러리 오브젝트 39개가 같은지 확인합니다. 실제 다항식 C/AVX2 분기를 기록하고 API 전체 구간과 중첩 비용을 구별합니다.
- 커널 송신 요청의 바이트 ID는 TCP 세그먼트 ID가 아닙니다. 누적 ACK 알림과 사용자 공간 패킷 관측 시각을 따로 기록하며 종료 뒤 관측 대기를 주 측정 구간에 넣지 않습니다.
- CPU 표본을 수집한 실행은 시간 모드여도 진단 자료입니다. 양쪽 중 하나라도 프로파일링하면 일반·반복 컨텍스트 자동 성능 비교에서 제외합니다.

상세 계약은 [공통 실행·계측 계약](../design/prototype.md), 출처·재현 가정은 [논문 재현](../experiments/research-reproduction.md), 실행 근거는 [검증 범위](validation.md)에 있습니다.

## 남은 연구 작업과 완료 판정

첫 ML-KEM-768 비교는 upstream wolfSSL 5.8.2의 C/AVX2 쌍으로 고정했고 실제 경로를 확인했습니다. 후보 논문의 AVX-512 구현 재현이라고 부르지 않습니다. [ML-KEM 비교](../experiments/mlkem-comparison.md)와 [논문 재현](../experiments/research-reproduction.md)의 출처를 구별합니다. 새로 채택한 기법의 공개 코드가 없다면 논문 요구사항을 구현 위치·정상 검증에 대응시킨 명세를 작성하고 직접 구현합니다. 채택한 BiTHaC에는 저자 코드가 있어 직접 구현 대체 경로를 사용하지 않았습니다.

TCP 강화는 무손실·MTU·초기 윈도·송신 정책 뒤 특정 바이트 단일 손실과 랜덤 손실을 검증했습니다. 지정 손실은 연결·방향별 첫 전송 한 번만 제거합니다. 실제 qdisc 제거와 `tcp_retransmit_skb`는 BTF 기반 커널 사건으로 기록하고 기존 패킷 중첩량과 구별합니다. 네트워크 프로필 schema 3과 TCP 분석 schema 2가 추가됐으며 이전 네트워크 프로필 1·2와 TLS 원자료의 뜻은 보존합니다.

총 CPU 계수와 perf 표본 비중은 별도이며 [CPU 분석](../analysis/cpu-profiling.md)에 실제 이벤트·범위·도구 경고를 보존합니다. 일반 시간·추적·CPU 수집의 관측 부담을 본 실험 장비에서 평가해야 합니다.

본 실험 전 반복 수, 컨텍스트 재사용, 캐시 준비, 네트워크 조건, 주 지표·통계를 동결합니다. 실패 시행과 관측 누락, 미지원·해당 없음·실제 0을 보존합니다. 현재 로컬 구현과 검증 결과는 [구현 보고서](implementation-report.md)에 모읍니다. 논문의 정확한 timer 경계는 공개 정보로 확정되지 않았고 네이티브 Linux·ARM은 사용자 요청으로 유보했습니다. 이 항목까지 포함한 전체 연구는 미완료입니다.
