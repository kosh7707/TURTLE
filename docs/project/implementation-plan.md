# 구현 범위와 변경 절차

2026-11-16 기준으로 전면 재설계의 소스 계약·공통 실행기·세 라이브러리 경계·연구 기능·보고서가 구현되어 있습니다. 완료된 구현 순서를 새 작업 목록처럼 반복하지 않습니다. 현재 구조는 [프레임워크 설계](../design/architecture.md), 실행 증거는 [검증 기록](validation.md)에 있습니다.

유지할 범위는 인증서 기반 TLS 1.3 정상 경로, 네 시나리오, 역할별 측정, 소스 함수표로 연결한 구현체, 공통 실행·관측 모델입니다. 구형 API·ABI·설정·원자료·보고서·제어 형식의 호환 계층과 동적 구현체 로더는 두지 않습니다. 과거 원자료는 보존하고 현재 판독 대상에서 제외합니다. 웹과 CLI 제품화는 범위 밖입니다.

다음 논의의 제안은 [설계 논의](../design/discussion.md)에 있습니다. 이 문서의 권고만으로 새 구현 범위가 승인된 것은 아닙니다. 현재 자동 비교 조건과 버퍼·상태 순서의 제한도 현재 설계에 명시했습니다.

변경할 때는 연구 질문과 바뀌는 계약을 정하고, 해당 부품의 선언·구현·예제·자료 해석을 함께 갱신합니다. 메시지 경계를 바꾸면 결정적 순서·바이트 시험과 실제 TLS를, 측정·보고서를 바꾸면 비용 귀속·가용 상태·독립 표본을 확인합니다. 빌드·의존성을 정리하면 오프라인 입력과 활성 빌드·실행 경로가 남아 있는지 확인합니다. 중요한 선택 이유는 [결정 기록](DECISIONS.md)에 남깁니다.

시험 수로 계측 전체의 정확성을 주장하지 않습니다. 물리 NIC·ARM·다른 커널의 PMU·native Linux 성능 순위는 WSL 기능 검증으로 확정하지 않습니다. 강건성·공격·인증서 거절·타이밍 누출 시험, 보안과 성능의 관계와 학회 적합성 판단은 범위 밖입니다.
