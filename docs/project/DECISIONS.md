# 현재 설계 결정

## 방법론과 구현 경계

TURTLE은 Linux용 C++20 프레임워크다. 논문 본문에서 방법론을 구성하는 실행·계측·원자료 해석·유효성 판정은 C++에서 수행한다. 통계 보고서와 의존성 준비·개발 검증은 선택적 유틸로 `tools/`에 둔다. 프레임워크는 이 유틸을 호출하거나 import하지 않는다.

공개 계약은 C 함수표·불투명 TLS 상태·바이트 버퍼다. 바이너리 플러그인 ABI는 제공하지 않는다. 소켓과 시계·기록 버퍼·실행 순서는 프레임워크가 소유하며 구현자는 TLS 컨텍스트·연결과 라이브러리별 설정을 소유한다. 코어에 라이브러리 이름별 분기를 넣지 않는다.

## 프레임과 관측 경계

원래 TLS 레코드 앞에 `TU` 2바이트와 방향별 uint16 네트워크 순서 번호를 붙인다. 번호는 1부터 시작하며 재사용하지 않는다. 수신 시 프레임만 제거하고 TLS 바이트를 공개 I/O 연결로 전달한다. 헤더 분할·다중 레코드·부분 I/O를 지원하며 전체 레코드 완성을 기다리지 않는다.

프레임 위치·소켓 제출 방식·공개 호출 경계는 C++ 전환에서 유지했다. ClientHello, ServerHello, 서버 암호화 묶음, 클라이언트 Finished의 관측 구간을 분석한다. 서버 인증 1-RTT 프로파일의 선언과 성공한 공개 호출을 사용하며 암호화 메시지를 복호화하거나 내부 생성·검증 비용으로 해석하지 않는다.

## 네트워크와 성능 관측

세 네임스페이스와 두 veth 쌍을 사용하고 중간 네임스페이스의 수신 측 방향 출력에 netem을 둔다. 기준 구성도 같은 토폴로지를 사용한다. C++ libpcap 수집기는 TCP 연결 전에 준비 완료를 알린다. 송신 측 캡처의 중복 TCP 바이트를 재전송으로 집계하며 netem 설정 손실·qdisc 제거·캡처 드롭과 구별한다.

카운터는 호출 스레드의 사용자 공간 cycles·instructions를 `perf_event_open`으로 읽는다. 부분 스케줄 값은 보정하지 않는다. CPU 표본은 별도 실행의 공식 perf record/script를 사용하며 저장한 ELF 객체로 해석한다. `NO_LIBPYTHON=1`로 빌드한 perf와 연결 의존성을 확인한다. 계측 실행은 일반 시간 통계에서 제외한다.

## 저장과 보고서

이식성과 구현 안정성을 위해 JSON·JSONL을 유지하고 nlohmann/json을 사용한다. 시각·카운터·바이트는 정수로 저장한다. 문자열 구성·파일 출력·해석은 엔드포인트 측정 구간 밖이다. 실제 0·미수집·미지원·누락을 구별한다.

C++ 분석 v4의 `measurements`에 단위·수집 상태·통계 포함 여부·제외 이유를 명시한다. 보고서 유틸은 manifest와 분석 결과만 읽고 중앙값·IQR·기준 차이·부트스트랩을 계산한다. 원자료 해석과 유효성 판정을 중복 구현하지 않는다.

## 재현성과 프로젝트 구조

구성·빌드·CTest에는 Python과 네트워크 다운로드를 요구하지 않는다. 의존성 준비는 별도 단계이며 공식 소스의 체크섬과 옵션을 기록한다. 외부 CMake 소스·기설치 라이브러리·Make 기반 등록과 공개 C 계약을 검증한다. 개인 경로나 외부 프로젝트를 런타임 출처로 조회하지 않는다.

빌드·테스트·실행 산출물은 `out/` 아래에 분리한다. 2026-11-17 사용자 지시에 따라 이전 빌드·실험 산출물과 보고서를 폐기했다. 새 실행에서는 실패·중단한 시도를 남기며 교체하지 않는다. 외부 보관 디렉터리와 Git 이력은 수정하지 않는다.

Linux ARM64를 고려한다. 현재 개발 호스트에서 실제 실행을 확인하고 ARM64용 프레임워크·구현체를 교차 빌드한다. 실제 보드의 TLS·netem·PMU 검증은 보드가 준비된 뒤 수행한다. wolfSSL 5.9.4의 GCC 15 ARM64 빌드는 upstream AES 코드의 `stringop-overflow` 경고 때문에 해당 경고의 오류 승격만 해제했으며 소스는 수정하지 않았다. 이 빌드 결과는 보드 실행의 검증을 대신하지 않는다.
