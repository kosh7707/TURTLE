# 현재 구현 결정과 이유

현재 유지하는 설계와 그 이유를 정리합니다. 실행 방법은 [문서 안내](../README.md), 지원 범위와 남은 작업은 [구현 계획](implementation-plan.md)을 따릅니다.

## 실행 범위와 소유권

정상 인증서 기반 TLS 1.3 전체 핸드셰이크와 암호화된 응용 교환을 비교합니다. 클라이언트와 서버를 따로 측정하며 PSK·세션 재개·클라이언트 0-RTT·HRR는 기준 시나리오에서 제외합니다. 공격·비정상 인증서·타이밍 누출·학회 적합성은 연구 범위에 넣지 않습니다.

프레임워크가 프로세스·소켓·비차단 입출력·대기·버퍼·셋업·종료를 소유합니다. 라이브러리별 코드는 공개 계약을 구현하는 공유 모듈로 분리합니다. 지휘 프로세스에서 TLS를 초기화하지 않아 자식의 할당 훅 설치와 라이브러리 상태를 미리 바꾸지 않습니다. 외부 C 할당 API가 사용자 인자를 받지 않을 때만 어댑터 안에 비소유 `thread_local` 포인터를 허용합니다.

`director.cpp`는 시도·자식·네트워크 인계를, `role_runtime.cpp`는 한 엔드포인트의 셋업과 연결 반복을 맡습니다. 자식 제어 메시지와 합성 조회는 각각 `endpoint_protocol.cpp`, `lookup_runtime.cpp`에 둡니다. 한 번만 쓰는 단순 전달·변환 함수는 호출 위치에 두되, 소유권이나 독립된 작업 단위를 드러내는 함수는 유지합니다. 공통 상태를 여러 변수에 중복 저장하거나 필요 없는 범용 서비스 계층을 만들지 않습니다.

## 시행과 계약 버전

실행 순서는 `모듈 로드 → 컨텍스트 셋업 → 시행 준비 동기화 → 새 TCP → 연결 객체 준비 → TLS·응용 → 정리`입니다. 소켓을 미리 연결하면 TCP 비용과 상태가 측정 밖으로 이동하므로 시행마다 새로 연결합니다. TLS 역할의 `RLIMIT_NOFILE`은 유지하고 `RLIMIT_NPROC=0`만 적용합니다. 서버 accept 대기, 클라이언트 connect, 연결 객체 준비와 프로토콜 비용을 나눕니다.

공개 ABI 3, TLS 원자료 schema 2, 측정 계약 개정 3을 사용합니다. 각각 바이너리 배치, 저장 형식, 측정 의미를 식별하므로 독립적으로 관리합니다. 로더는 `turtle_adapter_v3`만 호출하며 다른 함수표를 재해석하지 않습니다. 기존 원자료를 읽을 때도 당시 측정 의미를 보존하고 다른 개정의 수치를 소급 보정하지 않습니다.

기본은 컨텍스트당 측정 연결 1개, 워밍업 0회입니다. 재사용 조건에서는 첫 측정 연결도 보존하고 같은 컨텍스트의 연결들을 독립 표본으로 세지 않습니다. `--context` 입력은 실행 시작에 읽은 같은 저장본을 각 새 프로세스에 전달합니다. 표본의 출력 상태를 다음 표본의 입력으로 자동 누적하지 않습니다. 반복 컨텍스트 대표값은 별도 보고 옵션으로 계산하며 [집계·비교 조건](../analysis/reporting.md)을 충족해야 합니다.

## 시나리오와 계측 경계

네 시나리오는 순수 핸드셰이크, 분리된 서버 Ping, Finished와 Ping 결합, 클라이언트 요청·서버 응답입니다. 서버의 `ApplicationWriteReady`는 ClientFinished 처리 전 응용 키 준비를 뜻하며 전체 핸드셰이크 완료와 구별합니다. 측정 종료점을 지나도 양쪽은 인증과 정상 시나리오를 끝까지 수행합니다.

`native`와 `server-hello-first` 송신 정책은 계측 설정과 독립입니다. Finished와 Ping의 결합은 레코드·키 경계를 유지한 출력 배치이며 TCP 세그먼트 하나를 보장하지 않습니다. 프레임워크 버퍼 수용과 실제 소켓 제출 완료를 별도로 남깁니다. 논문 기법이 바꾸는 사전 연산·캐시·송신 정책은 비교를 위해 제거하지 않습니다.

공개 평문 알림은 종류·순서 대조용이며 생성·검증 시간으로 쓰지 않습니다. 실제 내부 구성·처리·레코드 암복호화 구간을 `TraceSink`로 전달합니다. wolfSSL의 넓은 `library_message_write`와 레코드·I/O 전에 닫는 생성 구간은 중첩하므로 더하지 않습니다. Mbed TLS 바디 생성 밖의 준비·마무리 비용도 구별합니다. 구현별 대응 위치와 한계는 [공통 실행·계측 계약](../design/prototype.md)에 둡니다.

기준 키 공유 생성은 핸드셰이크 안에서 수행하고 연결 객체 준비와 섞지 않습니다. I/O 반환의 스트림 복사와 사건 공간 준비는 반환 스냅샷 전에 두어 프레임워크 I/O 비용으로 분류합니다. 시계·카운터 읽기와 관측자 복귀 비용은 여전히 남으므로 연산 구간을 순수 암호 비용이라고 부르지 않습니다. 측정 중에는 선확보 버퍼를 사용하고 해석·JSON·파일 출력은 뒤로 미룹니다.

## 관측 가능성과 비교

정상 TLS 완료, 지표 가용성, 자동 비교 적격성은 별개입니다. 관측 불가·미지원·해당 없음·누락과 실제 0을 구별합니다. 실패 시행을 삭제하거나 성공 수를 채우려고 재시도하지 않습니다. 최초 실패 이유와 전체 시도 분모를 보존합니다.

OpenSSL의 라이브러리 직접 소켓 경로는 프레임워크 I/O를 거치지 않습니다. 보이지 않는 스트림을 0바이트로 처리하거나 서버 첫 수신 기반 주 구간을 다른 시작점으로 대체하지 않습니다. 채널 관측자 끔은 관측 함수 포인터만 비우며 호출·대기·키 로그 등의 비용은 남습니다. 공통 호출 경계는 별도 진단 지표이고 켬/끔 차이로 전체 계측 비용을 복원하지 않습니다.

CPU 총 시간·계수와 perf 함수·모듈 표본 비중을 분리합니다. `perf_scope`는 요청·지원 상태·실제 범위를 따로 기록하며 명시적 `user+kernel`을 적용하지 못하면 `user`로 낮추지 않습니다. CPU 프로파일링 실행은 일반 자동 시간 비교에서 제외합니다. 수집 당시 build ID와 일치하는 바이너리를 보존해 재분석하고, 심볼이 없는 표본도 분모에 남깁니다. build ID 없는 임시 vDSO는 함수 이름을 unknown으로 두며 일반 파일의 ID 불일치를 허용하지 않습니다.

메모리 계측은 할당 훅이 관측한 요청 바이트입니다. 할당기 내부 여유·전체 RSS·스택 최고 사용량으로 확대하지 않습니다. CPU 위상·SMT 형제와 실제 고정 성공을 기록하지만 WSL의 CPU 배치를 호스트 물리 코어 독점 사용의 증거로 삼지 않습니다.

## 로컬 네트워크와 손실 관측

한 호스트의 클라이언트·라우터·서버 네임스페이스와 veth 두 쌍을 사용합니다. TLS 프로세스는 클라이언트·서버 두 개이며 서버 수신 대기 포트 하나로 양방향 통신합니다. 라우터의 수신자 방향 출구에서 netem을 각각 적용하면 두 방향의 조건을 독립적으로 고정할 수 있습니다. Docker는 필수 의존성으로 추가하지 않습니다.

일반 실행은 user namespace 격리를 사용합니다. 커널 관측을 요청한 실행만 BPF 권한을 위해 initial user namespace의 root를 유지하고 새 network namespace에서 수행합니다. 이 경로의 TLS 엔드포인트도 root이므로 권한 종류를 비교 조건에 포함합니다. 호스트 네트워크를 바꾸지 않고 실행 소유 링크·프로세스·FD를 정리합니다.

MTU·offload·소켓·속도·초기 cwnd는 요청값과 실제 재조회값을 구별합니다. 안정된 설정은 그룹 조건에 넣지만 PID·포트·시각·손실 결과는 넣지 않습니다. 단계 참조뿐 아니라 qdisc·요청한 추적 본문, 호스트 불변과 정리 완료를 확인해야 자동 비교에 포함합니다. 실패를 별도 조건처럼 분리하지 않습니다.

지정 바이트 손실은 SYN 다음을 0으로 센 위치를 포함하는 첫 payload 패킷 전체를 연결·방향별 한 번 제거하고 재전송을 통과시킵니다. tc/eBPF의 실제 제거, `tcp_retransmit_skb`, netem qdisc 제거와 패킷 관측의 바이트 중첩은 서로 다른 관측량입니다. 네트워크 프로필 schema 3과 TCP 분석 schema 2는 TLS 원자료 버전과 별개입니다.

원본 pcap의 IP/TCP 헤더·옵션·payload와 시계 교정 구간을 보존합니다. AF_PACKET 소프트웨어 프레임을 물리 NIC 프레임이라고 부르지 않습니다. `TX_SCHED`·`TX_SOFTWARE`·`TX_ACK`는 TCP 요청의 마지막 바이트에 대응하며 패킷별 정확한 시각을 뜻하지 않습니다. 종료 뒤 최대 100ms의 ACK 관측 대기는 주 측정 구간에 넣지 않습니다.

## 논문 기법과 보조 조회

BiTHaC는 저자 공개 코드의 wolfSSL 5.7.0 기반에서 캐시 끔/켬 쌍을 유지합니다. 기법 코드와 TURTLE 실행·계측 패치를 구별하며 실제 캐시 송신 함수와 Certificate 바이트 변화를 함께 확인합니다. 새 프로세스로 빈 캐시를 만들고 첫 연결 준비 비용을 남깁니다. 논문 실험별 라이브러리 판과 정확한 timer 경계의 미확정 부분은 [재현 명세](../experiments/research-reproduction.md)에 기록합니다.

첫 ML-KEM-768 비교는 같은 wolfSSL 5.8.2 소스의 C/AVX2 경로입니다. 두 관련 C 소스의 컴파일 분기만 바꾸고 나머지 오브젝트 39개의 동일성과 실제 호출 분기를 확인합니다. 전체 암호 최적화 설정을 바꾸면 다른 연산의 효과가 섞이기 때문입니다. 내부 해시·표현·임시 메모리 차이는 기법의 일부이며 API 전체와 내부 구간을 더하지 않습니다. 후보 AVX-512 논문 구현의 재현으로 표시하지 않습니다.

합성 인증서 조회는 별도의 `synthetic-lookup-plus-standard-tls` 조건입니다. 조회 응답을 검증·소비하지만 실제 TLS Certificate를 축소하지 않습니다. 조회 캐시는 연결마다 같은 empty/fixed 저장본으로 복원하며 BiTHaC의 연결 간 누적 캐시와 구별합니다. 모의 CA는 TLS 역할을 흉내 내지 않는 별도 서비스 참여자입니다. 상세 계약은 [모의 CA](../experiments/mock-ca.md)에 둡니다.

## 의존성과 재현성

JSON 파서의 검증·유지보수 범위를 줄이기 위해 nlohmann/json 3.11.3 단일 헤더와 MIT 라이선스를 포함합니다. 측정 경로에서는 호출하지 않습니다. 원본 `v3.11.3` 헤더의 SHA-256은 `9bea4c8066ef4a1c206b2be5a36302f8926f7fdc6087af5d20b417d0cf103ea6`입니다. BPF 관측용 libbpf 1.6.3의 역할과 빌드 출처는 [TCP 분석](../analysis/tcp-analysis.md)에 명시합니다.

프로필·환경의 FNV-1a 64비트 지문은 식별용이며 보안 해시가 아닙니다. 이를 위해 지휘 프로세스에서 libcrypto를 초기화하지 않습니다. 입력 내용·라이브러리 판·컴파일 조건·패치 해시를 함께 보존하며 Git 정보가 없으면 없는 상태로 기록합니다. 시험은 의존성 다운로드를 수행하지 않습니다.

네이티브 Linux 본 실험과 ARM 재현은 사용자 요청에 따라 유보합니다. WSL의 기능 검증을 성능 순위나 전체 연구 완료로 표시하지 않습니다. 본 실험 전 반복 수·컨텍스트·캐시·네트워크·주 지표·통계를 동결하고 해당 장비에서 관측 부담을 평가해야 합니다.

## 문서 배치

설계 설명과 실험·검증 자료를 종류별로 찾을 수 있도록 `docs/` 바로 아래에는 안내용 `README.md`만 둡니다. 구조·계약은 `design/`, 원자료·분석은 `analysis/`, 실험·논문 재현은 `experiments/`, 계획·결정·검증은 `project/`로 나눕니다. 문서 생성기의 기본 출력도 이 배치를 따릅니다.

`docs/references/`에는 실제 논문·RFC 원문만 둡니다. 초기 명세·인계·검토·역할 배정과 중복 계획, 누적된 과거 결정·검증 서술은 `/tmp`로 옮겨 현재 설명과 분리했습니다. 문서 배치는 기존 원자료와 측정 의미를 바꾸지 않습니다.
