# 현재 구현 결정과 이유

현재 유지하는 설계와 그 이유를 정리합니다. 실행 방법은 [문서 안내](../README.md), 지원 범위와 남은 작업은 [구현 계획](implementation-plan.md)을 따릅니다.

## 2026-11-12 전체 점검과 현행 계약으로의 정리

최신 요청에 따라 실행 호환 경로와 TLS schema 1·2 판독을 제거합니다. 사용자가 원자료 판독도 현재 schema 3으로 제한한다고 명시했습니다. 구형 측정 종료 추정, 이웃 파일·`director.txt` 대체 판독과 C++ 시도 원장 작성기를 삭제합니다. 요청·시작·완료 분모는 외부 실행기 한 곳에서 기록하며 조회 보고서는 원장을 요구합니다. 서비스·조회·해독·분석의 독립된 schema 번호는 TLS 버전으로 바꾸지 않습니다.

제어 프레임에서 사용하지 않는 주소·부모 프로세스 관리 필드를 제거하고 프로토콜을 2로 올립니다. 고정 프레임은 277바이트이고 처음의 버전 합의와 같은 상수를 사용합니다. 어댑터 ABI 3과 측정 경계 개정 3은 그대로입니다. `Step::Done` 별칭은 삭제하고 값 2인 `Complete`를 사용합니다. 모듈 핸들은 RAII로 소유해 진입점 예외에서도 닫습니다.

주소 옵션은 역할별 IPv4:Port로 통일합니다. 독립 실행에는 TCP 데이터·제어 연결만 필요합니다. 외부 netem 관측을 요청할 때만 로컬 관측 소켓을 생성합니다. 관측기의 Unix 소켓은 준비·정리 경계용이며 TLS 데이터 전송 경로가 아닙니다.

네트워크 프로필은 schema 3으로 통일하고 순수 TLS 두 방향 또는 조회 포함 네 방향을 명시적으로 대조합니다. 네트워크 출처 형식은 외부 실행기를 `runner`로 식별하는 schema 2입니다. 네트워크 관측을 요청하지 않은 결과는 `not_requested`이며 원격 실행을 루프백이라고 추정하지 않습니다. 검증 결과는 [검증 기록](validation.md)에 통합합니다.

실제 회귀에서 클라이언트의 임시 데이터 포트가 제어 수신 포트 44331과 겹쳤습니다. 양쪽 포트 중 하나만 대조하던 패킷 분류는 이 데이터를 제어 흐름으로 잘못 분류했습니다. 방향에 따른 서버 포트로 패킷·커널 흐름을 식별하도록 수정하고, TLS·조회 양방향의 포트 중첩을 회귀 조건으로 넣었습니다. 같은 규칙으로 제어 연결의 임시 포트가 44330인 경우도 지정 손실에서 제외합니다. 실패 당시 원자료·캡처는 보존하고 수정된 분류로 별도 재분석했습니다. 측정 경계와 원자료 형식은 바뀌지 않습니다.

## 실행 범위와 소유권

정상 인증서 기반 TLS 1.3 전체 핸드셰이크와 암호화된 응용 교환을 비교합니다. 클라이언트와 서버를 따로 측정하며 PSK·세션 재개·클라이언트 0-RTT·HRR는 기준 시나리오에서 제외합니다. 공격·비정상 인증서·타이밍 누출·학회 적합성은 연구 범위에 넣지 않습니다.

2026년 11월 12일 독립 엔드포인트 계획을 반영했습니다. `turtle-client`·`turtle-server`는 각각 구성·빌드·배포·실행할 수 있습니다. `endpoint.cpp`가 자기 입력·제어 연결을 준비하고 `role_runtime.cpp`가 어댑터·계측기·기록·소켓의 수명을 관리합니다. 공통 공개 ABI 3은 그대로 두고 기본 `builtin`과 명시적 `module` 연결 방식을 프레임워크 메타데이터로 구별합니다. 내장 방식은 선택한 구현 하나만 연결하며 TLS 라이브러리 자체의 링크 방식과 혼동하지 않습니다.

로컬 반복·CPU 배치·프로세스 회수·시도 원장은 외부 `scripts/run-local.py`로 옮겼습니다. 네트워크 실행기는 기존 소유 네임스페이스에 독립 실행 파일을 배치합니다. 기존 `director.cpp`, `turtle run`과 평면 프로필의 실행 호환 경로는 제거했습니다. 엔드포인트는 자기 CPU만 선택하므로 한 장비에 여러 로컬 물리 코어가 있어야 한다는 조건을 원격 엔드포인트에 적용하지 않습니다.

설정은 공유 시나리오, 자기 엔드포인트, 외부 실험으로 나눴습니다. 준비 단계에서 필요한 값만 TCP 제어 연결로 교환하고 시행마다 별도 TLS TCP를 만듭니다. 절대 단조 시각을 전송하지 않고 각 엔드포인트가 같은 제한 길이로 자기 기한을 정합니다. 원자료는 실행·컨텍스트·연결 ID로 결합하고 교차 장비 시각 차이는 교정 없이는 계산하지 않습니다.

### IP:Port 연결과 준비 확인 (2026년 11월 12일)

최신 사용자 요청에 따라 SSH 배포·실행 자동화를 필수 후속 기능으로 두지 않습니다. 실행 중인 엔드포인트의 데이터·제어 IP:Port를 지정하고 TCP 접속과 시험 준비를 확인하는 공통 `PeerSession`을 구성 지점에 연결했습니다. 배포·독립 표본을 위한 프로세스 재시작·결과 회수는 외부 실행 환경의 책임입니다.

기존 `endpoint.cpp`의 소켓 생성·소유권을 `PeerSession`으로 옮기고 `role_runtime.cpp`에 명시적으로 전달합니다. 소켓은 어댑터 컨텍스트보다 오래 살아 있습니다. 접속, 시나리오 합의, 자기 준비, 상대 준비를 구별하며 실제 계측 지원을 교환합니다. TLS 측정 전에 JSON 교환을 끝내고 같은 제어 연결을 완료·중단까지 유지합니다. 확인용 TLS 접속은 첫 연결·캐시 상태를 바꿀 수 있어 추가하지 않습니다. 데이터 경로와 인증의 실제 성공은 첫 시행에서 판정하고 실패 표본을 보존합니다.

기존 제어 프로토콜 2의 준비 JSON에 `readiness_version=1`을 명시해 준비 교환을 이해하지 못하는 상대와 시작하지 않습니다. 조회 서비스는 별도 세션에서 0을 사용합니다. 원자료 schema 3과 측정 계약 개정 3은 유지하고 `preparation`을 추가합니다. 보고서에는 준비 요약과 실패 단계를 보존하며, 준비 교환 버전을 양쪽 비교 조건에 포함합니다. 과거 자료의 준비 상태는 추정하지 않습니다.

Linux IPv4 소켓 설명과 OpenSSL 3.5.4 `apps/s_time.c`의 `BIO_s_connect`→`SSL_connect` 경로를 확인했습니다. 루프백도 TCP이며 물리 NIC 사용 여부는 주소 문자열만으로 판정할 수 없습니다. `s_time`의 연결 성능 집계는 TURTLE의 양쪽 개별 계측이나 강건성 시험을 대신하지 않습니다. 전송 경로·출처·적용하지 않은 집계 방식은 [실행 문서](../design/runtime.md#로컬-tcp와-물리-네트워크)에 설명합니다.

### 관찰한 소스와 채택한 원리

SUPERCOP 로컬 `20261018`, 커밋 `200cd30`의 `crypto_hash/sha256/ref/api.h`, `okcompilers/do`, `cpucycles/do`, `cpucycles/wrapper.c`, `do-part`를 읽었습니다. 작은 구현 계약, 컴파일·실행으로 확인하는 지원, 준비 단계의 계측 선택과 작업·출처 분리를 채택했습니다. 대상 실행으로 확인하는 부분은 TURTLE의 대상 장비 준비 단계에 두며 교차 컴파일 호스트에서 실행하지 않습니다. 타이머 환산을 PMU 사이클의 대체값으로 삼는 정책은 채택하지 않았습니다. `/tmp/supercop`과 참고 연구 폴더는 수정하지 않았습니다.

Spring Framework `7.0.10`의 구성·의존성 해결·생명주기를 관찰했습니다. 생성자에 필요한 객체를 전달하는 원리와 `refresh`의 준비→구성→초기화, 실패 시 `destroyBeans`로 정리하는 순서를 참고했습니다. C++에서는 지역 객체와 RAII로 이 순서를 표현하며 Spring 런타임·전역 컨테이너·서비스 조회기는 도입하지 않습니다. [의존성 주입 문서](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html), [관찰한 생명주기 소스](https://github.com/spring-projects/spring-framework/blob/v7.0.10/spring-context/src/main/java/org/springframework/context/support/AbstractApplicationContext.java).

외부 C 할당 API에 사용자 인자가 없을 때만 어댑터 내부의 비소유 `thread_local` 포인터를 허용합니다. 그 포인터가 서비스나 계측기를 소유하지는 않습니다. 연결과 컨텍스트를 먼저 파괴하고 이를 지원한 서비스·모듈·계측기를 나중에 정리합니다.

## 시행과 계약 버전

실행 순서는 `어댑터 연결 → 컨텍스트 셋업 → 시행 준비 동기화 → 새 TCP → 연결 객체 준비 → TLS·응용 → 정리`입니다. 소켓을 미리 연결하면 TCP 비용과 상태가 측정 밖으로 이동하므로 시행마다 새로 연결합니다. TLS 역할의 `RLIMIT_NOFILE`은 유지하고 `RLIMIT_NPROC=0`만 적용합니다. 서버 accept 대기, 클라이언트 connect, 연결 객체 준비와 프로토콜 비용을 나눕니다.

공개 ABI 3, TLS 원자료 schema 3, 새 실행의 측정 계약 개정 4를 사용합니다. 각각 바이너리 배치, 저장 형식, 측정 의미를 식별하므로 독립적으로 관리합니다. 로더는 `turtle_adapter_v3`만 호출하며 다른 함수표를 재해석하지 않습니다. TLS schema 3의 개정 3·4를 판독하며 다른 개정의 수치를 소급 보정하지 않습니다.

기본은 컨텍스트당 측정 연결 1개, 워밍업 0회입니다. 재사용 조건에서는 첫 측정 연결도 보존하고 같은 컨텍스트의 연결들을 독립 표본으로 세지 않습니다. `--context` 입력은 각 엔드포인트가 자기 저장본만 읽습니다. 외부 실행기는 매 표본에 같은 입력을 지정할 수 있습니다. 표본의 출력 상태를 다음 표본의 입력으로 자동 누적하지 않습니다. 반복 컨텍스트 대표값은 별도 보고 옵션으로 계산하며 [집계·비교 조건](../analysis/reporting.md)을 충족해야 합니다.

## 시나리오와 계측 경계

### 마지막 TLS API 반환과 계측 증거 (2026년 11월 12일)

계측 검증 중 사용자는 시나리오의 종료를 마지막 TLS 메시지나 응용 데이터의 처리 완료로 정했고, 송신에서는 소켓 제출보다 **TLS 송신·핸드셰이크 API의 성공 반환**을 선택했습니다. 수신에서는 TLS 검증·복호화가 끝나 응용 버퍼로 반환하는 것까지입니다. 소켓 정리 비용은 주 구간에 추가하지 않습니다.

기존 구현은 순수 핸드셰이크의 인증 결과 조회나 응용 완료 표식을 종료로 기록했습니다. 명시한 새 종료 의미를 기존 자료에 조용히 덮어쓰지 않도록 측정 계약을 4로 올립니다. 공개 ABI·JSONL schema·제어 프로토콜은 구조가 같아 각각 3·3·2를 유지합니다. `end_sequence`에는 이미 캡처한 마지막 성공 `CALL_END`를 넣고 새 타이머 읽기를 추가하지 않습니다. 역할별 상세 경계와 앞선 패턴 확인 비용의 포함 여부는 [실행 계약](../design/runtime.md#시나리오의-종료-개정-4)을 따릅니다.

개정 3 판독은 이번 검증의 실패 원자료와 기준선을 재분석하기 위해 유지합니다. 판독기는 기록된 종료 사건을 그대로 사용하고 4의 경계로 추정·변환하지 않습니다. 자기 역할과 상대 역할의 개정값을 비교 조건에 유지하여 서로 다른 개정을 합치지 않습니다. schema 1·2, 종료점 추정, 구 실행 명령의 호환 경로는 되살리지 않습니다.

계산 합계가 맞는다는 사실만으로 관측을 완전하다고 보지 않습니다. 누락된 I/O 사건 쌍이 연산으로 흡수되는 것을 순번 검증으로 차단하고, 불완전한 분해는 숫자 대신 null과 이유를 남깁니다. 힙 최고치는 시작의 현재량과 뒤따르는 모든 독립 스냅샷의 구간 최고치로 계산합니다. 첫 수신의 `KERNEL_RX`는 같은 읽기의 복사본이므로 시작 이전 최고치를 다시 포함하지 않습니다. 한 스냅샷이라도 빠지면 관측한 부분 최고치를 전체 최고치로 보고하지 않습니다.

상대 머리글의 성공 표시는 상대 측정 사건의 완결성 증거가 아닙니다. 상대 자료가 부족하면 자기 역할의 설명용 지표는 유지하고 자동 비교에서 제외합니다. 요청한 연결 집합이 빠진 실행은 무효입니다. 이 원칙은 컨텍스트 재사용, 실패 분모와 첫 측정 연결 보존에도 적용합니다. 원자료가 쓰인 뒤 발생한 정리 실패는 기존 실패 표식·원장 경로로 계속 반영합니다.

확정 오류의 수정 전 실패·수정 후 결과와 미검증 한계는 [계측 검증 기록](validation.md#계측-의도와-실제-동작의-대조)에 연결합니다. 원자료가 없는 기능이나 다른 관측 위치의 시각을 임의로 0 또는 같은 시점으로 바꾸지 않습니다.

네 시나리오는 순수 핸드셰이크, 분리된 서버 Ping, Finished와 Ping 결합, 클라이언트 요청·서버 응답입니다. 서버의 `ApplicationWriteReady`는 ClientFinished 처리 전 응용 키 준비를 뜻하며 전체 핸드셰이크 완료와 구별합니다. 측정 종료점을 지나도 양쪽은 인증과 정상 시나리오를 끝까지 수행합니다.

`native`와 `server-hello-first` 송신 정책은 계측 설정과 독립입니다. Finished와 Ping의 결합은 레코드·키 경계를 유지한 출력 배치이며 TCP 세그먼트 하나를 보장하지 않습니다. 프레임워크 버퍼 수용과 실제 소켓 제출 완료를 별도로 남깁니다. 논문 기법이 바꾸는 사전 연산·캐시·송신 정책은 비교를 위해 제거하지 않습니다.

공개 평문 알림은 종류·순서 대조용이며 생성·검증 시간으로 쓰지 않습니다. 실제 내부 구성·처리·레코드 암복호화 구간을 `TraceSink`로 전달합니다. wolfSSL의 넓은 `library_message_write`와 레코드·I/O 전에 닫는 생성 구간은 중첩하므로 더하지 않습니다. Mbed TLS 바디 생성 밖의 준비·마무리 비용도 구별합니다. 구현별 대응 위치와 한계는 [공통 실행·계측 계약](../design/prototype.md)에 둡니다.

기준 키 공유 생성은 핸드셰이크 안에서 수행하고 연결 객체 준비와 섞지 않습니다. I/O 반환의 스트림 복사와 사건 공간 준비는 반환 스냅샷 전에 두어 프레임워크 I/O 비용으로 분류합니다. 시계·카운터 읽기와 관측자 복귀 비용은 여전히 남으므로 연산 구간을 순수 암호 비용이라고 부르지 않습니다. 측정 중에는 선확보 버퍼를 사용하고 해석·JSON·파일 출력은 뒤로 미룹니다.

## 관측 가능성과 비교

정상 TLS 완료, 지표 가용성, 자동 비교 적격성은 별개입니다. 관측 불가·미지원·해당 없음·누락과 실제 0을 구별합니다. 실패 시행을 삭제하거나 성공 수를 채우려고 재시도하지 않습니다. 최초 실패 이유와 전체 시도 분모를 보존합니다.

OpenSSL의 라이브러리 직접 소켓 경로는 프레임워크 I/O를 거치지 않습니다. 보이지 않는 스트림을 0바이트로 처리하거나 서버 첫 수신 기반 주 구간을 다른 시작점으로 대체하지 않습니다. 채널 관측자 끔은 관측 함수 포인터만 비우며 호출·대기·키 로그 등의 비용은 남습니다. 공통 호출 경계는 별도 진단 지표이고 켬/끔 차이로 전체 계측 비용을 복원하지 않습니다.

CPU 총 시간·계수와 perf 함수·모듈 표본 비중을 분리합니다. `perf_scope`는 요청·지원 상태·실제 범위를 따로 기록하며 명시적 `user+kernel`을 적용하지 못하면 `user`로 낮추지 않습니다. CPU 프로파일링 실행은 일반 자동 시간 비교에서 제외합니다. 수집 당시 build ID와 일치하는 바이너리를 보존해 재분석하고, 심볼이 없는 표본도 분모에 남깁니다. build ID 없는 임시 vDSO는 함수 이름을 unknown으로 두며 일반 파일의 ID 불일치를 허용하지 않습니다.

메모리 계측은 할당 훅이 관측한 요청 바이트입니다. 할당기 내부 여유·전체 RSS·스택 최고 사용량으로 확대하지 않습니다. CPU 위상·SMT 형제와 실제 고정 성공을 기록하지만 WSL의 CPU 배치를 호스트 물리 코어 독점 사용의 증거로 삼지 않습니다.

## 로컬 네트워크와 손실 관측

로컬 실험은 한 호스트의 클라이언트·라우터·서버 네임스페이스와 veth 두 쌍을 사용합니다. TLS 프로세스는 클라이언트·서버 두 개이며 데이터 수신 포트 하나로 양방향 통신합니다. 별도 제어 포트는 netem·지정 손실·TLS 바이트 집계에서 제외합니다. 라우터의 수신자 방향 출구에서 netem을 각각 적용하면 두 방향의 조건을 독립적으로 고정할 수 있습니다. Docker는 필수 의존성으로 추가하지 않습니다.

일반 실행은 user namespace 격리를 사용합니다. 커널 관측을 요청한 실행만 BPF 권한을 위해 initial user namespace의 root를 유지하고 새 network namespace에서 수행합니다. 이 경로의 TLS 엔드포인트도 root이므로 권한 종류를 비교 조건에 포함합니다. 호스트 네트워크를 바꾸지 않고 실행 소유 링크·프로세스·FD를 정리합니다.

MTU·offload·소켓·속도·초기 cwnd는 요청값과 실제 재조회값을 구별합니다. 안정된 설정은 그룹 조건에 넣지만 PID·포트·시각·손실 결과는 넣지 않습니다. 단계 참조뿐 아니라 qdisc·요청한 추적 본문, 호스트 불변과 정리 완료를 확인해야 자동 비교에 포함합니다. 실패를 별도 조건처럼 분리하지 않습니다.

지정 바이트 손실은 SYN 다음을 0으로 센 위치를 포함하는 첫 payload 패킷 전체를 연결·방향별 한 번 제거하고 재전송을 통과시킵니다. tc/eBPF의 실제 제거, `tcp_retransmit_skb`, netem qdisc 제거와 패킷 관측의 바이트 중첩은 서로 다른 관측량입니다. 네트워크 프로필 schema 3과 TCP 분석 schema 2는 TLS 원자료 버전과 별개입니다.

원본 pcap의 IP/TCP 헤더·옵션·payload와 시계 교정 구간을 보존합니다. AF_PACKET 소프트웨어 프레임을 물리 NIC 프레임이라고 부르지 않습니다. `TX_SCHED`·`TX_SOFTWARE`·`TX_ACK`는 TCP 요청의 마지막 바이트에 대응하며 패킷별 정확한 시각을 뜻하지 않습니다. 종료 뒤 최대 100ms의 ACK 관측 대기는 주 측정 구간에 넣지 않습니다.

## 논문 기법과 보조 조회

BiTHaC는 저자 공개 코드의 wolfSSL 5.7.0 기반에서 캐시 끔/켬 쌍을 유지합니다. 기법 코드와 TURTLE 실행·계측 패치를 구별하며 실제 캐시 송신 함수와 Certificate 바이트 변화를 함께 확인합니다. 새 프로세스로 빈 캐시를 만들고 첫 연결 준비 비용을 남깁니다. 논문 실험별 라이브러리 판과 정확한 timer 경계의 미확정 부분은 [재현 명세](../experiments/research-reproduction.md)에 기록합니다.

첫 ML-KEM-768 비교는 같은 wolfSSL 5.8.2 소스의 C/AVX2 경로입니다. 두 관련 C 소스의 컴파일 분기만 바꾸고 나머지 오브젝트 39개의 동일성과 실제 호출 분기를 확인합니다. 전체 암호 최적화 설정을 바꾸면 다른 연산의 효과가 섞이기 때문입니다. 내부 해시·표현·임시 메모리 차이는 기법의 일부이며 API 전체와 내부 구간을 더하지 않습니다. 후보 AVX-512 논문 구현의 재현으로 표시하지 않습니다.

합성 인증서 조회는 별도의 `synthetic-lookup-plus-standard-tls` 조건입니다. 조회 응답을 검증·소비하지만 실제 TLS Certificate를 축소하지 않습니다. 조회 캐시는 연결마다 같은 empty/fixed 저장본으로 복원하며 BiTHaC의 연결 간 누적 캐시와 구별합니다. 모의 CA는 TLS 역할을 흉내 내지 않는 별도 서비스 참여자입니다. 상세 계약은 [모의 CA](../experiments/mock-ca.md)에 둡니다.

## 의존성과 재현성

JSON 파서의 검증·유지보수 범위를 줄이기 위해 nlohmann/json 3.11.3 단일 헤더와 MIT 라이선스를 포함합니다. 측정 경로에서는 호출하지 않습니다. 원본 `v3.11.3` 헤더의 SHA-256은 `9bea4c8066ef4a1c206b2be5a36302f8926f7fdc6087af5d20b417d0cf103ea6`입니다. BPF 관측용 libbpf 1.6.3의 역할과 빌드 출처는 [TCP 분석](../analysis/tcp-analysis.md)에 명시합니다.

프로필·환경의 FNV-1a 64비트 지문은 식별용이며 보안 해시가 아닙니다. 설정 식별을 위해 TLS 라이브러리를 초기화하지 않습니다. 입력 내용·라이브러리 판·컴파일 조건·패치 해시를 함께 보존하며 Git 정보가 없으면 없는 상태로 기록합니다. 시험은 의존성 다운로드를 수행하지 않습니다.

네이티브 Linux 본 실험과 ARM 재현은 사용자 요청에 따라 유보합니다. WSL의 기능 검증을 성능 순위나 전체 연구 완료로 표시하지 않습니다. 본 실험 전 반복 수·컨텍스트·캐시·네트워크·주 지표·통계를 동결하고 해당 장비에서 관측 부담을 평가해야 합니다.

## 로컬 실험 웹과 재현 보관 (2026-11-12)

최신 요청에 따라 실험 웹은 `~/TURTLE-experiment-web`의 별도 로컬 저장소로 만들고 TURTLE의 실행·계측·해독 계약은 확장하지 않습니다. 웹은 보고서의 통계·비교 판정을 사용하고 BigInt로 원자료 정수와 각 엔드포인트의 독립 축을 보존합니다. 같은 실행의 복수 보고서는 사용자가 선택하며 파일 시각으로 최신성을 추정하지 않습니다.

레거시 정리는 기존 독립 엔드포인트 변경을 유지하고 참조가 확인된 현재 연구 기능을 보존하는 범위입니다. 중복 설정 키·자기 대입과 오래된 경계 설명만 추가로 정리했습니다. 비활성 산출물은 삭제하지 않고 지문·원래 위치와 함께 보관했습니다. 관리자 소유 파일 하나의 해시는 읽기 권한 때문에 미확인이며 동일 inode와 메타데이터로 rename 보존을 확인했습니다. 소스·의존성·빌드·설치·시험용 인증서를 별도 경로에서 재현하는 절차와 한계는 [로컬 웹·재현 기록](local-web-reproduction.md)에 남깁니다.

같은 날 후속 요청으로 미사용 레거시 빌드는 삭제하는 것으로 바꿨습니다. 보관했던 빌드 11개와 현재 시험 빌드의 폐기된 타깃 잔여물을 삭제했습니다. 빌드 폴더에 섞인 시험 원자료·실패 기록·인증서·구성 기록은 분리해 지문을 확인하고, 현재 빌드와 최신 재현 근거는 유지합니다. 소스 코드와 현재 CMake 타깃은 바꾸지 않았습니다. [삭제·보존 범위](local-web-reproduction.md#후속-요청에-따른-레거시-빌드-삭제)에 현재 상태를 기록했습니다.

## 공통 빌드 헬퍼 (2026-11-12)

빌드 명령을 관리하기 쉽게 하려는 후속 요청에 따라 기존 `scripts/`에 `build.sh`를 두고, `check.sh`의 의존성 선택·CMake 구성을 이 헬퍼로 모았습니다. 기본 모듈 빌드는 현재 `build-module`, 시험은 `build-tests-independent`를 사용하며 내장 구현체·클라이언트 전용·서버 전용·분석 전용 구성은 각기 다른 폴더를 기본값으로 갖습니다. 준비된 의존성만 사용하고 다운로드는 `build-deps.sh`에서 따로 수행합니다. `check.sh`의 Release/Debug 분리와 반복 기본값 20회는 유지합니다. 명령과 경로 재정의는 [스크립트 사용법](../../scripts/README.md)에 기록합니다.

## 의도와 관측값의 일치 (2026-11-12)

다양한 정상 시나리오를 점검하라는 후속 요청에서 `output_flush`가 반환하는 `IoResult`를 호출 종료 사건에 보존하지 않던 오류를 확인했습니다. 기존 필드에 요청량·처리량·상태·시스템 오류를 기록하며 실행 순서와 측정 경계는 유지합니다. 원자료의 부분 전송과 `WantWrite` 재시도를 독립 대조하고 이전 실패 로그를 보존합니다.

보고서의 그룹 적격 필드는 일부 조건만 반영해 진단 모드나 상대 자료 누락에도 참으로 남을 수 있었습니다. 내보내는 적격 필드에 실제 비교의 단일 그룹 조건을 적용하고 제외 이유를 기록합니다. 통계·원자료와 두 그룹의 비교 규칙은 그대로입니다. 기존 196개 보고서를 다시 생성해 이를 확인했습니다. 로컬 웹도 원자료 경계 시각·계약·식별자를 확인하고 연결 수 합계 한도를 맞췄습니다. [범위와 근거](intent-audit.md)를 따릅니다.
