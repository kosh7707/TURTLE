# 설계 결정

## 2026-11-12: 소스 계약으로 전면 교체

이전 어댑터 ABI와 전체 handshake 호출을 감싼 실행기는 연구자가 논리 메시지의 실행 순서와 전송을 통제할 수 없었습니다. 이를 제거하고 C 함수표와 함께 컴파일하는 구현체별 엔드포인트로 바꿨습니다. 구형 판독기·모듈 로더·별칭·버전 분기는 두지 않습니다. 참고할 과거 원자료는 그대로 보존합니다.

메시지 본문 생성·처리와 전후 상태 전환을 분리했습니다. transcript·Finished 준비·키 전환·캐시 삽입 비용은 명시적인 전환 사건입니다. OpenSSL도 private statem·record 메서드를 패치해 사용하며, 공개 API 제약을 전체 handshake 호출로 우회하지 않습니다. 메모리 BIO는 내부 레코드 바이트 전달용이고 네트워크 수단이 아닙니다.

레코드·출력 배치·소켓 호출·패킷은 별개입니다. 메시지와 레코드는 평문 범위, 레코드와 TCP는 스트림 범위로 연결합니다. 공유 비용은 한 번만 기록하고 메시지별 독립 비용으로 배분하지 않습니다. Finished+Ping은 두 레코드가 같은 출력 배치에 있는 조건입니다.

Black-box와 white-box는 동일한 실행기를 사용합니다. 서버 첫 읽기 대기는 양쪽의 대칭적인 시나리오 진입 경계에 포함합니다. peer 완료 제어 대기와 사후 파일 출력은 제외합니다. 프레임워크 준비와 TCP 준비도 별도 기록해 숨은 준비 비용을 줄였으며 첫 사용 비용은 측정한 준비와 첫 연결 비용의 합으로 정의했습니다.

할당을 라이브러리별 계측 코드로 구현하지 않고, 실행기가 구현체 호출을 감싸는 링크 할당 어댑터를 사용합니다. 계측 상태는 Observer가 소유합니다. C allocator에는 user argument가 없어 비소유 thread-local 포인터만 허용했습니다. 관측 범위를 정적으로 연결한 요청 할당에 한정하며 RSS·숨은 libc 할당·정확한 구간별 peak라고 설명하지 않습니다.

BiTHaC 저자 코드의 owning global cache는 컨텍스트로 옮겼습니다. 라이브러리의 일반 전역 런타임 초기화가 모두 사라졌다고 주장하지 않으며 독립 프로세스·컨텍스트를 표본 단위로 유지합니다. MockCA는 합성 객체 실험이고 TLS 인증서 대체가 아닙니다. CPU 표본은 별도 실행의 period 비중입니다.

통계는 Python의 정수로 원자료를 해석합니다. 연결 위치별 분포와 컨텍스트 대표값을 구분하며, 전체 배치의 실패·누락이 있으면 자동 비교를 만들지 않습니다. 같은 상대 구현체를 고정하지 않은 self-pair 기법 비교는 조건별 기술통계로 보존합니다. StQ나 탐색 부트스트랩을 성능 결론으로 확대하지 않습니다.

자격 증명 준비도 역할·인증 모드로 제한했습니다. 서버 인증에서 클라이언트의 자기 인증서·키와 서버의 신뢰 CA를 미리 읽던 불필요한 작업을 제거했습니다. 상호 인증에서는 양쪽에 모두 필요하므로 유지합니다. 준비 비용과 첫 사용 비용은 이 선택을 manifest에 남겨 해석합니다.

BiTHaC의 캐시 켬/끔 교차 연결을 반복하는 정상 경로에서 원본 코드의 잠금 반환 누락을 확인했습니다. 이미 저장한 서버 인증서를 다시 삽입하지 않고 반환할 때도 보유 잠금을 해제하며, peer index 반복의 잠금 상태를 초기화하고 반환값과 맞춥니다. 중복 캐시 삽입에 넘겨받은 새 버퍼도 소유권 계약에 따라 해제합니다. 캐시를 지원하지 않는 상대와 네 연결을 연속 실행하는 양방향 시험을 추가했습니다.

## 2026-11-13: 묶음 레코드의 전환 순서 명시

완료 감사에서 공개 헤더의 `COMMIT_SEND` 설명이 묶음 정책을 반영하지 못하는 것을 확인했습니다. 묶음 레코드를 채우기 위해 후속 메시지를 조립하려면 먼저 앞 메시지의 transcript를 갱신해야 합니다. 전환의 전제는 메시지 조립 완료이며, Hello·Finished의 키 전환 때만 남은 평문의 보호를 반드시 먼저 마칩니다. 이 기존 실행 순서를 계약과 구현자 문서에 명시했습니다. 결정적 시험은 구현체가 제공된 버퍼보다 적게 생산·소비하는 진행도 확인하고 상세 계측 구간이 서로 겹치지 않는지 검사합니다.

같은 감사에서 서버 데이터 소켓의 생성·bind/listen이 준비 합계에서 빠진 것을 확인했습니다. 이 작업을 `listener-preparation`으로 두 계측 깊이에서 측정하고 첫 사용에 한 번 포함했습니다. 필수 준비 사건과 TCP 측정이 없는 경우에는 합계를 null로 남겨 실제 0과 구분합니다. 제어 연결·출력 파일 준비는 기존처럼 프로토콜의 준비 비용과 구별합니다.

큰 인증서 시험도 기본 TLS 레코드 크기를 넘도록 강화했습니다. 이전의 10,000바이트 확장은 약 11KB Certificate를 만들었으므로 작은 레코드의 분할은 검증했지만 기본 16KB 레코드의 분할은 검증하지 못했습니다. 32,768바이트 확장을 넣은 약 34KB Certificate에서 wolfSSL의 기존 `MAX_CERTIFICATE_SZ` 상한이 정상 처리를 막는 것을 확인했습니다. TURTLE 경로에서는 이미 연결에 지정한 `max_message` 용량을 사용하도록 wolfSSL·BiTHaC 경계를 수정했습니다. 프레임워크 밖의 원래 경로는 기존 상한을 유지합니다. 세 라이브러리 교차 연결에서 127바이트와 16KB 레코드를 모두 검증하고, ML-KEM·BiTHaC 네 구현에서도 같은 큰 인증서로 컨텍스트당 세 연결을 완료하도록 시험에 포함했습니다.

응용 데이터의 조립 사건에도 생산 길이를 기록하고, 처리 사건의 조각 시작 위치를 누적 수신량으로 기록하도록 보완했습니다. 핸드셰이크와 응용 메시지 모두 조립·처리 조각이 겹침·누락 없이 해당 메시지 전체를 덮는지 결정적 시험으로 검사합니다. 단계 사건의 범위는 메시지 내부 위치이며 레코드·소켓 사건의 TLS 스트림 위치와 구분하도록 원자료 문서에 명시했습니다.

## 2026-11-16: 활성 빌드·검증 이력·설계 논의 분리

반복 검증 빌드가 루트에 남아 활성 경로와 과거 증거를 구별하기 어려웠습니다. 활성 빌드를 `build-message`와 `build-message-tests`로 정리하고, 과거 검증 자료와 native 개발 스냅샷은 `artifacts/build-history/2026-11-16`으로 이동했습니다. 최종 오프라인 검증본은 전체를 보존하고 다른 빌드의 재생성 가능한 생성물을 제거했습니다. 원자료 안의 경로·해시는 고치지 않으며 이동 원장으로 보존 위치를 설명합니다. 고정 원본·현재 의존성·perf·libbpf 입력은 유지했습니다. 커널 관측기의 기본 출력을 `build-message`, 시험 PKI의 기본 출력을 `pki/default`로 맞춰 구형 `build/` 경로가 다시 생기지 않게 했습니다.

현재 설계 문서에는 코드로 확인한 소유권, 단계·보호 경계, 역할별 완료, 버퍼, 비용 계산, 자료와 비교의 제한을 모았습니다. 완료된 구현 순서를 미래 작업처럼 반복하던 계획 문서는 현재 범위와 변경 절차로 정리했습니다. 자동 비교 조건의 누락, 고정 상태 순서, 조각 인터페이스와 스트리밍의 차이 등은 실제 동작으로 설명하고, 다음 선택지는 별도의 설계 논의에 두었습니다. 이 문서 정리로 프로토콜이나 보고서의 동작을 변경하지는 않았습니다.
