# 논문에 사용할 수 있는 주장 범위

이 문서는 원고가 아니라 구현에서 확보한 근거와 남은 실험을 정리한 메모입니다. 투고처 적합성이나 성능과 보안의 연결 논증을 새로 끌어오지 않습니다.

## 현재 코드로 확인할 수 있는 것

- 서로 다른 TLS 구현체가 하나의 공개 계약을 구현하고 같은 정상 실행 흐름과 원자료 형식을 사용할 수 있습니다.
- 프레임워크가 TLS 메시지를 대신 만들지 않고도 실제 TCP의 송수신 함수 경계를 관측할 수 있습니다.
- 같은 연결의 양쪽 바이트가 일치하는지, 레코드를 해독한 종류가 라이브러리 알림과 맞는지, 역할별 토막 합이 정한 구간 길이와 같은지를 검사할 수 있습니다.
- 원자료에서 역할·모드·프로필·상대 구현을 구별하여 통계와 분포를 다시 생성할 수 있습니다.
- 보이지 않는 협상값이나 카운터를 실제 0과 구별하여 기록할 수 있습니다.

## 아직 주장할 수 없는 것

- 기존 논문의 수치가 잘못됐다는 결론, TURTLE 결과가 무조건 더 정확하다는 결론은 없습니다.
- 모든 C/C++ TLS 구현이 수정 없이 들어간다거나, 모든 메시지의 독립 연산 시간을 잰다는 주장은 성립하지 않습니다.
- 계측기의 영향을 제거했다거나 네트워크 지연과 순수 연산 시간을 완벽히 분리했다는 근거는 없습니다.
- WSL의 기능 시험 수치를 라이브러리 성능 순위나 최종 논문 수치로 쓰면 안 됩니다.
- 독립 표본 부트스트랩의 구간이 시간적 상관이나 묶음별 변화까지 자동으로 해결하지 않습니다. 묶음별 대표값 변화도 함께 보아야 합니다.

## 다음 검증의 초점

논문의 목표는 큰 성능 역전 사례를 찾는 것이 아니라 **같은 대상이라는 조건을 명시하고, 그 조건 안에서 무엇이 실제로 비교됐는지 추적할 수 있게 하는 것**입니다. 구현이 있다는 것과 비교 타당성이 충분히 검증됐다는 것은 구별합니다.

우선 같은 상대 구현·인증서·암호 설정·출발 상태·계측 모드에서 표본을 모으고, 원자료의 실제 협상값과 메시지 종류를 확인합니다. 다음으로 관측 수준을 바꾼 실행과 독립적인 기준 관측을 대조하여 추가 계측이 만든 차이를 평가해야 합니다. NewSessionTicket은 기본 0장과 명시적으로 켠 경우를 따로 다루며, 어느 경계에 티켓 처리가 들어왔는지 바이트·메시지·사건으로 설명합니다.

외부 연구 기법의 재현은 별도 작업입니다. 아직 수행하지 않은 비교를 예상 결과나 가상의 수치로 채우지 않습니다.
