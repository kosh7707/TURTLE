# TURTLE 구현 계획

## 목표와 완료 기준

정상 경로 TLS 1.3 전체 핸드셰이크를 실제 TCP에서 실행하고, 같은 계약으로 시간·자원·바이트를 관측하는 프레임워크를 완성합니다. 두 역할의 원자료에서 오프라인 해석과 요약을 다시 생성할 수 있어야 합니다. 실제 라이브러리와 모의 구현의 결과를 구별합니다.

1. 소스와 테스트는 별도로 빌드하며 확인 스크립트로 반복 검증할 수 있어야 합니다.
2. OpenSSL, wolfSSL, Mbed TLS 어댑터는 코어 내부 헤더 없이 빌드해야 합니다. 지원되는 공통 프로필에서 서버 인증, 상호 인증, 라이브러리 간 연결을 검증합니다.
3. 새 역할 프로세스, 준비 완료 신호, 실제 TCP, 비차단 호출 반복, 암호화된 핑퐁, 컨텍스트 보존, 무효 상태 기록이 동작해야 합니다.
4. 측정 경계, 스레드 CPU 시간, 가능한 성능 카운터, 별도 메모리 모드, 환경과 계측 가능 여부를 원자료로 남깁니다.
5. 해석기는 실제 전송 바이트와 키 로그에서 메시지를 확인하며, 요약기는 구간 합과 역할별 분포를 원자료에서 다시 계산합니다.
6. 시험과 예제 실행 기록, 재현 방법, 알려진 지원 범위, 명세에서 바꾼 결정과 남은 확장 목표를 문서에 남깁니다.

## 작업 순서와 소유권

먼저 어댑터 계약, 내부 값 구조, 부품 공개 헤더를 리더가 고정합니다. 그 뒤 다음 네 영역을 병렬로 구현합니다.

| 작업자 | 소유 범위 |
|---|---|
| worker-1 | `src/lifecycle/`, `src/control/`, `src/transport/`, `src/main.cpp`, `implementations/mock/`, 해당 테스트를 맡습니다. |
| worker-2 | `src/measure/`, `src/capability/`, 해당 테스트를 맡습니다. |
| worker-3 | `implementations/openssl/`, `implementations/wolfssl/`, `implementations/mbedtls/`, TLS 의존성 빌드와 인증서 스크립트, 어댑터 테스트를 맡습니다. |
| worker-4 | `src/record/`, `src/interpret/`, `src/report/`, 원자료 형식 문서와 해당 테스트를 맡습니다. |

리더는 공개 계약, 내부 공통 값 구조, 설정 읽기, 최상위 빌드와 테스트 통합, 확인 스크립트, 최종 검증과 문서 인계를 맡습니다. 작업자는 다른 영역을 수정하지 않으며 필요한 계약 변경을 먼저 알립니다. 각 영역의 독립 빌드와 테스트를 먼저 확인하고, 통합 실행은 필요한 부품이 준비된 뒤 진행합니다.

## 범위의 경계

공격·강건성·잘못된 인증서 거절 시험은 제외합니다. 장비에 없는 계측을 대신 만들어 내지 않습니다. 모의 CA와 공개 연구 기법의 완전한 재현은 핵심 정상 실행과 계측을 검증한 뒤 가능한 범위에서 다루며, 미완료 항목을 완료라고 쓰지 않습니다. 이미 실행 중인 스택을 임의로 칠하는 구현은 하지 않습니다.

## 인계 전 정리 계획

새 공개 계약의 프로세스·준비 신호·격리·정상 TLS 시험을 먼저 고정한 뒤, 사용처가 없는 이전 `implementation.hpp` 계약을 지웁니다. 새 동작을 숨기는 호환 계층은 추가하지 않습니다. 처음의 README는 설계 이력으로 보존하고, 최상위 README에는 현재 실행할 수 있는 명령과 한계를 씁니다. 모듈 경계 검사와 정적 검사를 다시 실행하여 정리 전후의 동작을 확인합니다.

자동 시험으로 동작을 고정한 뒤 프로젝트의 C++ 파일에 저장소의 `.clang-format` 규칙을 한 번 적용합니다. 외부 헤더와 생성 파일은 건드리지 않습니다. 이 정리는 의미 변경을 의도하지 않으며, 같은 통합 시험과 정적 검사를 다시 통과해야 합니다.
